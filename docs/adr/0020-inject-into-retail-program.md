# 0020 可以往原版程序里注入代码，做原版引擎做不到的事

状态：accepted（2026-11-05）。取代 [0019](0019-port-game-logic-by-layer.md) 里"注入新模块是另一条路，要单独定，本条不包括"那一条。0019 其余部分不变：Python 模型仍只是认知工具，本身不进游戏。

## 背景

用户原话（2026-11-05）："既然我们已经用了DLL注入的方式做帧率解锁，那注入原版程序应该是可以的，ADR需要更新"。

先例：配音 mod 的安装器从 v1.1 起，把开源的高帧率插件 SAGE-Unlocked（GPL-3.0）做成可选项附带，后来换成我们自己的修复版。

它的做法是：
- 往游戏的 Data 文件夹放一个代理 DLL（`d3d9.dll`，也可以编成 `dinput8.dll`）；
- 游戏启动时，按字节特征码在内存里找到补丁点再打补丁，磁盘上的原版文件一个字节都不改；
- 删掉这几个文件就恢复原样。

这条路已经在玩家机器上跑了几周。踩过的坑记在 `work/re/fps-unlock-survey.md`：
- 改到逻辑就联机不同步；
- 换个发行版就找不到特征码；
- 找不到补丁点时悄悄跳过，结果单位隐形；
- "帧"有两种含义，混用 119 处。

0019 排除注入，是因为当时担心三件事：玩家安装方式、联网、许可。先例说明这三件都有办法处理，所以把这条路正式打开。

## 决定

1. **注入是正式的路**。用在两类事上：
   - 原版引擎做不到的机制，比如愿望单里的空中建筑、导弹、无人机；
   - 画面这一侧的改进，比如高帧率。

   能用数据（INI、XML、地图脚本）做到的，仍然先用数据做。
2. **只用一种形式**：代理 DLL 加内存补丁。补丁点靠特征码找，不写死地址；原版文件在磁盘上不改；删掉 DLL 就能完全恢复。不直接改程序文件本身。
3. **先模型，后注入**。凡是改游戏逻辑的注入，先在私有的 Python 模型里写出来（[0018](0018-engine-model-private-repo.md)、0019），再照着模型实现，用测试台对拍。模型就是注入代码的规格说明。
4. **找不到就明说**。某个补丁点找不到时，关掉依赖它的功能，并在日志和界面上说明是哪一项，不再悄悄跳过。关卡依赖的机制一旦没装上，必须在开局时就报出来，不能让玩家打到一半才发现。
5. **改逻辑的要过联机检查**。只改画面的（帧率、画质）可以做成可选项。改逻辑的：
   - 所有参加同一局的人必须装同一个版本；
   - 版本号要能让游戏或启动器发现两边不一致；
   - 每次改动都要跑录像回放的一致性检查，这套检查沿用配音线给高帧率插件做的那一套。
6. **安装走安装器或 mod 启动器**。DLL 只由安装器或 mod 自己的启动方式放进去、拿出来。各线会话不手动往 Steam 游戏目录里放文件；"不改 Steam 游戏目录里的文件"这条对原版文件照旧有效。开发时在测试台上验证。
7. **公开**：
   - 基于 GPL 代码改出来的部分（比如 SAGE-Unlocked 分支），分发二进制时照 GPL 附源码，这件事已经在做；
   - 我们自己写的注入模块里，补丁点和特征码是逆向得来的。照"只用来做mod，研究学习里面的内容，不公开"，源码先放本机私有，什么时候公开由用户定。在用户定之前，这类模块只在本机和测试台上用，不随 mod 分发。

## 否决的做法

- **直接改 `.game` 或 exe 文件**：要动玩家的原版文件，没法一键还原；不同发行版要各出一份补丁；Steam 校验文件时会被还原。
- **把 Python 模型嵌进游戏里跑**：模型是给人和 Agent 看懂引擎用的，速度和打包方式都不适合在游戏里跑。注入代码另外用 C 或 C# 照模型写。
- **只靠数据 mod，永远不注入**：空中建筑、可被拦截的导弹这类机制，数据层做不出来，只能绕路做半成品。

## 后果

- 愿望单里数据层做不到的机制，现在可以按"模型 → 注入 → 对拍 → 联机检查"这条线做。
- 多了维护负担：每支持一个发行版都要验证特征码，每改一次逻辑都要跑联机检查。
- 杀毒软件可能误报代理 DLL，部分联机平台的反作弊也可能拦。要在安装器和说明里写明，改逻辑的部分先只用于战役。
- 第 7 条和"帮整个社区产出新内容"的愿景有冲突：不公开，社区就用不上。这要等用户定公开的时机。
