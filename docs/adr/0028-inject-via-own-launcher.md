# 0028 新引擎功能的代码由我们自己的启动器注入，不改 Steam 游戏目录

状态：accepted（2026-11-09）。补充 [0027](0027-engine-extension-by-injection.md) 第 3 条第 4 问（"玩家安装时要多装什么"），并把 0027 第 1 条"以 `d3d9.dll` 挂进游戏"限定为测试台专用；[0020](0020-inject-into-retail-program.md)"DLL 只由安装器或 mod 启动方式放"一条在这里选定为"启动方式"。

## 背景

注入的代码必须进游戏进程，只放 mod 文件夹做不到。两条路：往游戏目录放一个 `d3d9.dll` 代理，游戏启动时自动加载；或者由我们自己的启动器启动游戏，启动时把代码注入进去。

用户原话（2026-11-09）："mod 本来就是需要有启动方式的"。

## 决定

1. **玩家通过我们的启动器启动带新功能的 mod**：启动器拉起游戏进程，在模块工厂建好模块表之后、加载数据之前把我们的代码注进去（注入时机由引擎扩展线 D 定）。
2. **不往 Steam 游戏目录放任何文件、不改游戏文件**。测试台副本（`work/testbench/RA3`）里的 `d3d9.dll` shim 仍只给测试台用。
3. **硬约束：玩家玩原版或别的 mod 时完全不受影响**（用户 2026-11-09 定）。只有经我们的启动器、且加载的是我们的 mod 时才注入；直接从 Steam 或原版启动器启动，或加载别的 mod，游戏进程里不能有我们的代码。不留常驻程序、不改注册表、不改游戏文件、不改全局设置。
4. **验收要能验证第 3 条**：至少查原版启动、别的 mod 启动两种情况下，游戏进程的模块列表里没有我们的 dll，且启动器退出后没有我们的进程留着。
5. 第一次在真游戏上跑注入前先问总控。

## 否掉的方案

- **游戏目录放 `d3d9.dll` 代理**：要改玩家的 Steam 游戏目录；装了就对所有 mod、原版战役和联机都生效，卸载要玩家自己删；和测试台 shim 抢同一个文件名。mod 本来就要一个启动方式，启动器注入不多给玩家加步骤。

## 后果

- 0027 的第 4 问答案变成"装 mod + 用我们的启动器启动"，不再算"冲突、待拍板"。
- 启动器要能处理注入时机（挂起启动或等工厂建表），这是 D 线下一步的技术约束。
- 不经启动器直接开游戏时，新模块不存在：游戏照本体规则加载（未知模块怎么处理见 D 线试探结果），要在 mod 说明里写清。
