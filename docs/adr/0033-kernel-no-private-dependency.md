# 0033 内核对私有模型零依赖，私有部分只当插件

状态：accepted（2026-11-17）。取代 [0032](0032-one-rules-source-per-part.md) 第 2、3 条，其余几条不变。用户看了四块各管什么之后问："物体部分用的是我们自己加载的，脚本执行器写一个难度应该不大，遭遇战AI也可以自己写，玩家代理不是私有代码，那我们并不需要依赖私有模型吧？"

## 决定

1. **依赖只许从私有模型指向内核的端口，反过来不行**：内核不导入私有仓库的任何东西，也不知道它在不在。找插件、加载插件、核对版本放在内核外的入口。
2. **脚本执行器以公开实现为准**，照 `docs/engine/script-semantics.md` 和台上读数补完整；私有的脚本核心是接同一接口的可换插件，两份可以对照。
3. **玩家代理改成公开实现**，只经内核端口观测、下令。
4. **私有遭遇战 AI 是 AI 端口上的可选插件**：用来推演用了原版 AI 的关卡，以及让我们的 AI 和原版 AI 对打（[0034](0034-multi-battlefield-and-own-ai.md)）。
5. 没有私有模型时内核功能完整，内核测试全跑、不跳过（`docs/engine/sim-modules.md` 的守卫）；只少了"像原版那样打的 AI"。

## 否掉的方案

- **脚本核心和玩家代理留私有**（0032 原第 2、3 条）：脚本执行器公开那份已经有大半，玩家代理是我们自己设计的，没有理由让内核依赖私有仓库；依赖还逼着两边钉版本对齐。
