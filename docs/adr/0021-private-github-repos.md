# 0021 只在本机的成果推到 GitHub 私有仓库保存

状态：accepted（2026-11-05）。取代 [0018](0018-engine-model-private-repo.md) 里"不推送，不加远端"那一句；0018 其余部分不变（模型照反编译重写，不进公开仓库，本仓库按需加载）。

## 背景

用户原话（2026-11-05）："那就做成github私有仓库吧"，随后："本地的备份就不需要了"。

起因是看了 EXOR Studios 自研引擎的文章：知识只存在老员工脑子里，新人很难接手。我们这边对应的风险，是逆向成果和几个仓库只在这台电脑上，而这台电脑只有一块 C 盘。先做过一版本地每日备份，只能防误删，防不了坏盘，所以改成推到 GitHub 私有仓库。

## 决定

1. 四份只在本机的东西，各推到一个 GitHub 私有仓库（账号 77652189）：

   | 本机 | 私有仓库 | 远端名 |
   |---|---|---|
   | `RA3Modding/RA3-EngineModel` | RA3-EngineModel | origin |
   | `RA3-CampaignLab/work/re`（单独的 git 仓库，本仓库照旧忽略 `work/`） | RA3-RE-notes | origin |
   | `RA3Modding/RA3-ChineseVoice` | RA3-ChineseVoice-private | backup |
   | `RA3Modding/SAGE-smooth` | SAGE-smooth-private | backup |

2. **每次提交后都推到私有远端**。这些仓库不再是"只提交不推送"。
3. **公开的远端照旧不推**：
   - RA3-ChineseVoice 的 `origin` 是公开仓库，推送仍要用户授权；
   - SAGE-smooth 的 `fork`（公开的 SAGE-Unlocked 分叉）只在发布前、经用户同意才推。
4. **不改可见性**：这四个仓库一直保持私有，改成公开要用户明确同意。这一条和"只用来做mod，研究学习里面的内容，不公开"是同一个约束。
5. **`work/re` 不收游戏程序和 Ghidra 工程**（`.gitignore` 里有 `*.game`、`ghidra/`）：
   - `.game` 是 EA 的程序文件，不往网上传，私有仓库也不传；
   - Ghidra 工程里嵌着程序字节，单个文件 160 MB，超过 GitHub 的 100 MB 上限。

   Ghidra 里的函数命名和注释，如果需要保存，导出成不含程序字节的脚本或表格再收。

## 否决的做法

- **本地每日备份到同一块盘**：防不了坏盘。用户说不需要了，计划任务已删。
- **OneDrive**：同样是上云，还没有版本历史。
- **把逆向成果放进公开仓库**：违反"不公开"约束。

## 后果

- 坏盘、误删、换电脑都能从 GitHub 拉回来；会话清空后的接手材料也多了一处保存。
- 逆向成果第一次离开本机。安全靠两件事：GitHub 账号本身的安全，以及仓库一直保持私有。
- 各线提交后要记得推私有远端；`work/re` 的提交在它自己的仓库里做，不在本仓库。
