# 0018 引擎算法还原成可执行代码，放在本机私有仓库

状态：accepted（2026-11-04）。补充 [0017](0017-engine-layers-and-map-page.md)：0017 定了按层还原的顺序，本条定还原的产物是什么、放在哪里。

## 背景

用户原话（2026-11-04）："我希望尽可能把引擎的算法还原成python代码，这样我们后续就有一个稳定的地基，其他语言也可以"。

起因是寻路这一层。引擎线一条条在测试台上测具体场景，测出了"绕 1400 能过、1800 不过"这种阈值。阈值只是规则在某一种地形上的表现，多半来自搜索的预算上限，换一种地形形状就可能不准。拿它做地图检查，等于继续试错。

## 决定

1. **规则型的问题先读程序，写成可执行模型；测试台只用来核对。** 规则型指答案随地形或状态变化的，比如寻路、放置、索敌。答案只是"是"或"否"的问题（某个动作看不看冷却）仍直接上测试台。模型用 Python 写纯函数：输入地图数据，输出行为。每个模型配测试，期望值取自测试台的实测读数（`experimental/cnv/checks/engine_*.py`）。读不出的部分标"推断"，并写明为什么读不出。
2. **模型放在本机私有仓库 `RA3Modding/RA3-EngineModel`，不推送，不加远端。** 照反编译结果重写的算法等于反编译产物，而本仓库在 GitHub 上是公开的。用户 2026-11-04 原话："只用来做mod，研究学习里面的内容，不公开"。
3. **本仓库按需加载模型。** 路径从 `labpaths.ENGINE_MODEL` 取。模型仓库不在时，依赖它的检查一律跳过，不报错。本仓库里只留接口和行为结论：`docs/engine/` 写实测过的行为，不写地址、不写伪代码、不逐行转写算法。
4. 地址、伪代码、反汇编笔记仍只放 `work/re/`。

## 否掉的方案

- **把 GitHub 上的仓库改成私有，模型直接放进来**：最省事，但仓库从此不能公开。用户选了另开私有仓库。
- **模型只放 `work/re/`**：没有版本记录，丢了或改坏了都恢复不了。
- **继续只靠测试台测阈值**：每换一种地图形状就要重测，问题越积越多。

## 后果

- 已有的 `experimental/campaign/terrain_rules.py` 留在本仓库：它只含实测过的常量和行为规则，没有转写算法。以后照程序重写的算法，比如寻路模型，一律进私有仓库。
- 从干净的 clone 构建时，依赖模型的检查会跳过。我们只在国内发布成品 mod，不发布这个仓库的代码，所以这不影响发布。
- 引擎线同时管两个仓库，私有仓库的测试由引擎线自己跑。
