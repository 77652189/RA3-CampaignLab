# 0030 测试结果要能复现：私有引擎模型按版本锁住，生成的清单页不进仓库

状态：accepted（2026-11-17）。用户看过总控的架构检查后说"可以，按你的建议来"。

## 背景

2026-11-17 核全量红时发现：

- 模拟器运行时直接加载硬盘上 `RA3-EngineModel` 当时的工作树（`labpaths.ENGINE_MODEL`，可被 `CNV_ENGINE_MODEL` 改），和公开提交没有对应关系。`experimental/cnv/inventory_model.rev` 只给清单页用。结果：同一个公开提交，私有模型一变测试结果就变——B228 自己的提交 afb1273d 用现在的模型跑也红，按公开提交二分得不出结论。
- 生成的清单页（`docs/engine/inventory*.md`）提交在仓库里：11-15 起 352 个提交里 110 个是"重新生成清单页"，各线并行时这几个文件互相冲突，AGENTS.md 还专门有一条冲突处理规矩。

## 决定

1. **私有引擎模型按版本锁住**：公开仓库里记一个私有模型的提交号（沿用 `inventory_model.rev`），模拟器和 AI 加载模型时核对模型仓库的 HEAD 是不是这个提交，不是就报错停下，不悄悄用别的版本。改私有模型的提交和改版本号的公开提交一起推。干净克隆没有私有模型时照旧走 `model=False`。
2. **生成的清单页不进仓库**：`docs/engine/inventory*.md` 由脚本按需生成（`inventory.py` 等），不再提交；测试检查生成脚本能跑、结果自洽，不检查文件内容。
3. 由谁做：第 1 条改到 `sim.py` / `simai.py` 的加载部分，由重构线 R 在 ADR 0029 第 ④ 步之后、第 ⑤ 步之前做；第 2 条不碰模拟器，由引擎线 A 做。

## 否掉的方案

- **私有模型做成子模块**：公开仓库会出现指向私有仓库的引用，干净克隆和公开协作都会碰到拉不下来的子模块。
- **只在文档里提醒"二分前先对模型版本"**：靠人记，两条线同时改模型时照样各跑各的。
- **生成页留在仓库、只是少提交**：冲突和噪声少一点，根子不变。

## 后果

- 二分、全量、重构的逐帧比对都能复现：一个公开提交唯一确定模拟器用的模型。
- 改私有模型的线要多做一步：推模型后在公开仓库更新版本号；两条线同时改模型时会在版本号上冲突，这是想要的（逼着先合）。
- 想看清单页的人跑 `inventory.py` / `inventory_retail.py`，不再在 GitHub 上直接看。
