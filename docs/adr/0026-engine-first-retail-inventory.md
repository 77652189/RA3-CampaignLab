# 0026 引擎优先：以原版功能总清单为完成标准，原版战役关当验收题；关卡暂停推新内容

状态：accepted（2026-11-08）。取代 [0023](0023-simulator-as-daily-verifier.md)"后果"里"引擎线按覆盖清单补规则"、[0022](0022-simulator-before-levels.md) 里"关卡线只做支撑模拟器的事"的推进方式：引擎线不再按关卡缺口驱动。

## 背景

引擎线一直按关卡的覆盖清单补规则：关卡用到什么补什么。结果没有"做完"的定义，说不出还剩多少；关卡做到一半引擎补了规则，关卡就得回头重调。11-08 粗量：原版战役用到的 379 种脚本动作和条件，模拟器认得约 152 种（按原版用量加权约 77%，按名字匹配的粗数）；单位模块写了约 24 类，但原版一共用多少类没清点；AI 11 个部分都开了头，几条规则因一开就和测试台对不上而关着。

用户原话（2026-11-08）："引擎线给关卡线服务是依赖倒置的设计，我们应该先确保引擎线有实现原版各个功能的能力，然后再去做关卡，不然就得反复回头重做"；选了"引擎优先"。

## 决定

1. **原版功能总清单是引擎线的完成标准**：原版战役用到的全部脚本动作和条件、原版单位 XML 用到的全部模块类型、武器效果、AI 各部分。每项一个状态：已实现且有测试台对拍 / 已实现但推断 / 未做；按原版用量排先后。清单由脚本从原版数据生成，不手写，有测试守着（新出现的项自动进清单）。
2. **原版战役关是验收题**：同一份操作在游戏里和模拟器里各跑一遍，比结局和关键时间点（[0025](0025-playtest-in-game-replays-check-sim.md) 的录像比对工具）；对不上按 [0015](0015-fix-error-classes-at-source.md) 归因到规则。
3. **关卡线暂停推新关**：只做原版关验收题、自动玩家框架、题卡和数值区间的纸面打磨；手头 A4 对照局做完收尾。清单达标后再统一实装 9 关。
4. **自动玩家**：模拟器里按几种性格（平推、按兵种克制、照题卡巧解，各带随机扰动）下命令，只看玩家看得见的东西，命令走剧本动词（每局可导出成剧本上测试台复跑）；产出胜率、时长分布、捷径。框架可与引擎线并行搭，结论在清单达标前只作参考。

## 否掉的方案

- **折中（引擎按清单推进，关卡照常推进）**：引擎每补一条影响 AI 或索敌的规则，已调好的关卡就要重调，返工照旧。
- **维持按关卡缺口补**：没有完成标准，返工不止。

## 后果

- 引擎 A：脚本层、物体模块、武器的清单；录像比对工具。引擎 B：AI 部分的清单并按清单推进。
- 关卡线：原版关验收题（先查原版战役关能否存录像，不能就用测试台脚本驱动的检查代替）、自动玩家框架。
- 模拟器界面线：试玩版开关照做，跳阶段等关卡恢复后接存档点清单。
- 交给用户的 9 关试玩批次往后推到清单达标、关卡重新实装之后。
