# 0017 引擎各层都还原成参考；下一阶段做"能改的地图页"，图形化编辑器作长期目标

**背景**：2026-11-04，引擎线反编译游戏程序的可行性试探过了闸。它把脚本引擎这一层读清楚了：条件和动作怎么执行、字幕有两条通道、整队命令只对下令那一刻队里的单位有效、按钮放技能不看冷却。关卡线据此修掉了 E1～E6，这次是读代码写出适配的代码，没有再靠测试台一次次试。

别的几层还没摸过：放置和通行规则、地形、寻路、界面、资源打包。"冰墙在后巷口放不下"到现在还没查清，就是这一层的坑。

用户原话："另外几层我们尽量也深入研究一下吧，不然后续开发全都是坑，我们可以把下一个阶段定为能改的地图页，把图形化编辑器作为长期目标"。

**决策**：

- **引擎线按摩擦大小，逐层还原引擎。** 顺序：
  1. 放置和通行规则：技能、建筑在什么条件下放得下，坡度怎么判定能不能走。K3、K7 正卡在这里。
  2. 地形：高度、悬崖、贴图、水。
  3. 寻路和 AI 移动。
  4. 界面（APT，外壳线在用）。
  5. 资源打包：BinaryAssetBuilder 和资源流。
  6. 渲染和光照，放在最后。

  每一层的结论都要落到两处：
  - 测试台上的机关单测，或者构建时自动检查的产物规则；
  - 生成器或编译器的约束。

  只写在文档里不算数。

- **反编译的产物不公开。** 伪代码、函数地址、照着它们写的说明，都只放在本机的 `work/re/`。本仓库在 GitHub 上是公开的，所以只有测试台上实测到的行为，才能用我们自己的话写进 `docs/engine/`。

- **下一阶段是"能改的地图页"。** 它在攻略页的基础上做：
  - 你在地图上拖地点、画挡路、钉批注；
  - 页面只记下"改动提议"，不直接改地图；
  - Agent 拿到提议，去改地图模块，再跑一遍规则检查，然后重新发布页面。

  地图模块始终是唯一的来源，所以不会出现两边各说各的。

- **图形化编辑器是长期目标。** 等两件事都成立了再开工：一是地图页的用法已经被证明顺手；二是放置和通行、地形这两层已经还原清楚。编辑器的后端（地图读写、俯视预览、规则检查、原版对照）已经有了，到时候主要是加前端。

**后果**：
- 引擎线变成长期的线，要做好几轮。每一轮结束，只交两样东西：对我们代码的改法，加上测试。
- 地图页成了人和 Agent 一起改地图的入口，K7 的地形重排可以在页面上进行。
- 改关卡内容时还要不要连带改平台代码，这个比例要跟踪着看。现在大约是六成。

**否掉的方案**：
- 现在就做图形化编辑器：要 10 轮以上的会话，而且放置和地形规则还没摸清，编辑器背后的行为只能靠猜。
- 页面直接改地图文件：页面和地图模块会变成两份权威，迟早对不上。
- 只研究脚本引擎这一层：放置、地形这两层的坑会在每一张新地图上反复出现。
