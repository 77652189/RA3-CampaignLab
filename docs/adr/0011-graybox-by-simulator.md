# 0011 灰盒用模拟器做定性分析，实机由用户判断

取代 [0010](0010-question-first.md) 第 3 条里"用测试台无人值守跑打法脚本、不用离线模拟器"的部分。0010 的其余部分不变：课程表、题卡、配剧情、实装照旧，修法仍改模板不改单关。

**背景**：0010 打算让地图脚本替玩家这一方下命令，在真游戏里 8 倍速跑平推、拆源、巧解、失误四套打法，比读数。这要先做探针，再给每张卡写打法脚本、占测试台。用户 2026-10-30："我们不需要让关卡线进行完整的打法测试，只用模拟器做灰盒定性分析就够了，最后的实机测试可以让我进入游戏后判断"。

**决策**：
- 灰盒阶段由关卡线用 `experimental/cnv/sim.py` 对每张题卡做定性分析，不求精确数字。每张卡回答四个问题：
  1. 平推、拆源、巧解三种打法大致谁占优，差距大不大；
  2. 每一轮的最优应对会不会变；
  3. 拿掉卡上任何一项，巧解还成不成立；
  4. 简单档有没有安全网。
- 模拟器缺经济、敌方 AI 和部分武器数据（`docs/design/teardowns/data/simulator-gap-2026-10-30.md`）。只补回答这四个问题必需的最少部分；补不了的写明"模拟器判断不了，留给实机"。
- 先拿旧 A4 校准：它得判出"平推可以过"。
- 实机检验由用户进游戏判断，还是 0010 的两个问题："有没有'原来如此'的那一下"和"再玩一次会不会一样"。

**后果**：省掉探针、打法脚本和测试台时间，灰盒变快、变便宜。代价是定性结论比实机读数粗，分辨不了小差距，只能筛掉明显的坏题，细的判断全靠用户试玩。阶段闸门改为：模拟器连旧 A4 能平推都判不出来，就先停下重想。

**否掉的方案**：
- 照 0010 在测试台跑全套打法脚本：用户认为不需要，成本高。
- 补齐模拟器（2～3 周）做定量对比：定性分析够用，只按需补最少的数据。
