# 0029 模拟器按引擎部件分层，一块一块搬出 `sim.py`

状态：accepted（2026-11-16）。用户看过详细设计后定："优先让重构线做完再让其他的线做吧，这个太影响开发效率了"——由一条专门的重构线搬，搬完之前其他引擎线不改模拟器。边界和规矩见 [docs/engine/sim-layers.md](../engine/sim-layers.md)。

## 背景

用户 2026-11-16 问"为什么有大量测试内容需要跑，代码是否模块化，依赖是否清晰"，并说"只按会话拆分明显是不合理的"。量到的事实：

- `experimental/cnv/sim.py` 7166 行，`Sim` 一个类 5987 行、208 个方法；所有脚本动作在 `Sim.act` 一个函数里（1016 行，149 个分支，208 个动作名）。A、C、E 三条线的改动最后都落在这个文件。
- 已拆出的小模块里，驻军、渗透、扫射、维修、分配、AI 拿着整个模拟器对象读写内部；依赖实际是双向的。
- 每帧有 9 处把所有对象扫一遍，覆盖率把"跑到过"当成"依赖"，改一个模块会选中 184 个测试文件里的 110 多个。
- 测试几乎都是整局回放：全量约 16 小时 CPU，`test_simai_bench_b.py`（94 个测试，每个模拟 35–76 秒的整局）和 `test_simai.py` 两个文件占 62%。新建模拟器必须给一整个任务，没有最小世界的入口。
- 按引擎部件归层后，反向调用只有 37 条（39 处），多个层写同一字段的有 23 个；最多的是物体模块调单位命令的 `send`（9 条）。

## 决定

1. **按引擎的部件分层**（世界、数据、物体模块、战斗、玩家系统、单位命令、脚本、帧循环、遭遇战 AI、汇报），不按线分。
2. **依赖单向、一个字段一个主人、有部件才推进、帧顺序只写一处**，拆完一块就由守卫测试强制那一块。
3. **测试分两层**：最小世界的规则测试管日常；整局回放只做和台上读数的对拍证据。
4. **一块一块搬**，每一步纯搬家，用固定一组任务的逐帧事件记录前后一字不差来验收，再跑全量；旧方法先转调，没人用了再删。
5. 顺序按跨层边从少到多，先立脚手架和样板（顺序和进度在 plan.md）。
6. **搬完 ⑨ 后再做两步**（用户 2026-11-17 同意）：⑩ 把 `experimental/cnv` 做成真正的 Python 包，子包按层分（层就是目录，去掉 `sys.path.insert`；现在 191 个文件 290 处）；⑪ 测试按引擎部件重排，不再按线命名（`test_simai_bench_b` / `_c` 这类），配合两层测试。

## 否掉的方案

- **按线拆文件**：一项活常跨几层，线的划分会变；文件边界跟着人走，依赖照样乱。
- **测试加锁排队**：只是不抢 CPU，测试总量和"改哪都要跑一百多个文件"都没变。
- **只把最慢的两个文件挪到全量**：快了，但出错要等晚上全量才发现，结构问题原样留着。
- **推倒重写**：三条线天天在改这些规则，重写期间的改动没地方落；也没法保证行为不变。

## 后果

- 搬迁期间只有重构线改模拟器（`experimental/cnv/sim*.py` 及其测试）；引擎各线和 Codex 线先停，搬完再恢复。每块预计几小时到一天。
- "已对拍"的标准不变（有测试按名字跑台子、断言台上读数）；新增的规则测试是日常防回归用的，不顶替对拍。
- 挑测试的工具在搬完的部分改按导入关系挑，覆盖率只作补充。
- 私有引擎模型回调 `Sim.condition` / `Sim.action` 的接缝不动。
