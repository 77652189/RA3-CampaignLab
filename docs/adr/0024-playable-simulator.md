# 0024 模拟器做成能玩的：简单画面、字幕、配音、镜头，可跳段、可快进；玩法先在模拟器里验证

状态：accepted（2026-11-08）。补充 [0023](0023-simulator-as-daily-verifier.md)：第 2 条"模拟器原理上测不了的留给测试台和用户试玩"里，字幕和镜头的**时序与内容**、配音的**时机**、玩家的打法改由能玩的模拟器先验；第 4 条"试玩攒一批"的第一轮改在模拟器里玩。

## 背景

模拟器（`experimental/cnv/sim.py`）已经能跑关卡脚本和单位规则，`simshow.py` 能按秒读出镜头、台词、交还操作、目标和计数器，但只产出文字时间线，用户没法亲手打。进游戏试玩一局要十几分钟，开场过场不能跳，出问题要从头再来。

用户原话（2026-11-08）："给模拟器加上简单的图形界面和配音，字幕，镜头等需要测试的完整内容，变成实际可游玩，可跳过的模拟器，以后我们先在模拟器完成玩法验证，并且允许按阶段跳过，快进等，提高测试效率"。

## 决定

0. **对齐优先于界面**（用户原话 2026-11-08："最重要的一点是模拟器和游戏需要对齐，这是最优先事项，否则模拟器会成为新的bug来源"）：
   - 引擎线和关卡线的对拍、覆盖清单、对照局排在界面之前，界面线不占它们的测试台和额度；
   - 界面上把 `Sim.unmodeled` 和该关覆盖清单里的项直接标出来（"这里模拟器没模拟"），不让玩家把缺口当成玩法；
   - 一关只有覆盖清单只剩登记缺口、且最近一次对照局结局一致，才算"可在模拟器里试玩"，否则界面打开时先警告；
   - 用户在模拟器里报的问题，先在测试台上复现，分清是关卡问题还是模拟器没对齐，后者按 0015 从模拟器规则源头修。
1. **能玩的模拟器**：浏览器里的俯视画面（色块单位、地形轮廓、区域），玩家能选兵、移动、攻击、放技能、生产；屏幕上有目标、计数器、倒计时、字幕；台词按事件时间播报（有录音放录音，没有就用浏览器朗读）；过场时镜头跟脚本走、上下黑边、锁操作。
2. **省时间的控制**：暂停、1～8 倍和"尽快"快进；过场一键跳到交还操作；按阶段跳（阶段取自关卡的目标和标志链，跳过去用该关的全程脚本替玩家打到那里，或用存档点）。
3. **不改规则**：界面只经 `Sim` 的公开动作和读数，和 `simshow.py` 的 `ShowSim` 一样做外挂；需要模拟器新增读数的，交给引擎线 A 加。界面上的结局必须和同一份操作在 `simulate()` 里跑出的结局一致（有测试守着）。
4. **分工**：第一轮玩法试玩在模拟器里做；画面观感、音乐、手感、AI 随机感仍按 0023 留给测试台和最后的游戏内试玩。测试台的对拍和交付前验收照旧。

## 否掉的方案

- **继续只在游戏里试玩**：每局十几分钟，过场不能跳，改一个数要重开，用户试一轮成本太高。
- **用游戏引擎（Godot 等）重做画面**：工作量大，且两套规则会分叉；浏览器页面只是 `Sim` 的外壳，规则只有一份。
- **只给文字时间线**：用户看不出打起来的感觉，没法亲手验证"最自然的打法吃亏"。

## 后果

- 新开一条模拟器界面线，代码放 `experimental/simui/`，不碰 `sim.py`、`simunits.py`、`simai.py`。
- 给用户的试玩包先是模拟器版本（每关附一句"考什么"），游戏内试玩放在模拟器试玩通过之后。
