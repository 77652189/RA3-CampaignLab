# 0022 先把灰盒要用的逻辑都接进模拟器，关卡制作暂缓

状态：accepted（2026-11-07）。补充 [0019](0019-port-game-logic-by-layer.md) 第 1 条"画面、声音、界面不移植"：它们的**逻辑部分**要进模拟器，外观部分仍不移植。

## 背景

用户原话（2026-11-07）："关卡进度可以缓一缓，制作流程错了，效率低不说，后面还得推倒重来，我们之前直接写地图脚本不研究引擎就是一个明显的坑。逻辑部分接入模拟器是可行的。外观部分暂时不接也可以，外观和美术都放在最后调试，我们现在只管灰盒阶段能顺利进行"。

11-07 第四层做完、R1～R7 补进模拟器后，A4 的 7 项测试台检查都能在模拟器里真跑，代理玩家也能在模拟器里打 A4。但规则只覆盖 A4 用到的机制；别的关一碰到新机制（超武、空军、缺电、科技升级、技能冷却……）就得回测试台试，而镜头、台词时间线、过场交还操作、任务目标这类"玩家何时看到 / 听到 / 能做什么"的问题，模拟器完全不管。代理玩家在过场里偷跑、K1 台词来得太晚、K5 镜头拍到地图外，都是这类问题。

## 决定

1. **灰盒阶段要用的逻辑全部进模拟器**，分两块：
   - **通用机制**：超武、空军、缺电降速、科技升级、技能冷却与落点规则、生产等，加上第四层遭遇战 AI 接进模拟器当敌方。
   - **展示逻辑**：镜头（位置、取景里有什么、是否出界）、语音和字幕时间线（何时播、是否被盖、K1 规则）、过场流程（时长、何时交还操作）、界面状态（任务目标、计数器、小地图闪点）。
2. **做法照 ADR 0019**：先读程序或测试台量，再写成规则，再对拍；对不上记 strict xfail。
3. **外观不进模拟器**：画面、光照、特效、模型、声音本身、手感都留到最后，用测试台截图和用户试玩判断。
4. **关卡制作暂缓**：关卡线这段时间只做和模拟器、灰盒流程有关的事（提供关卡侧数据、核对模拟器结论），不推新关；等模拟器能支撑灰盒流程后再恢复出关。
5. **完成标准**：一关灰盒从改脚本 / 地图到判"打不打得通、玩家看到听到什么"，在模拟器里跑完，测试台只做新机制量规则和最后验收。

## 否掉的方案

- **按关卡需要逐步补通用机制、关卡同时推进**（总控原推荐）：每关都要先撞到新机制再回头补，和"直接写地图脚本不研究引擎"是同一种坑，后面还得返工。
- **外观也接进模拟器**：等于重写渲染器，规模巨大，最后仍要拿游戏画面比。

## 后果

- 关卡产出会停一段时间，27 关草稿的目标往后推。
- 引擎线继续占大部分额度；模拟器文件的所有权要在线之间分清。
