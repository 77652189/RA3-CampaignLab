# 0037 `Sim` 和 AI 大脑收成窄接口，分两期做，第二期看第一期的数字再定

状态：accepted（2026-11-21）。用户："按你推荐的分两期做"。

## 背景

[0029](0029-simulator-layers.md) 的分层搬迁做完后，部件都有了自己的家，但 `experimental/cnv/sim.py` 的 `Sim` 还挂着 162 个方法（其中 42 个只转手）、136 个字段：每个部件的状态都挂在它身上，部件之间靠 `Peers` 类互借 `Sim` 方法。`engine/ai/core.py` 的 `Brain` 一个类 1800 多行，对外大体走端口，但还有几处绕过端口直接读写世界。结果是改一处就得先读懂一个大文件，引擎线每一步约一半上下文花在"谁在用什么"的普查上。

普查（谁用了哪个 `Sim` 名字）和两份设计（`Sim` 一份、AI 大脑一份）都写好了，比过三条路：

- **一口气做完**：`Sim` 方法 162 → 约 40、`sim.py` 2639 → 约 1100 行，加上 AI 大脑拆文件，共约 17 个会话；后一半是 1000 多行的纯搬家，总行数基本不减，还和脚本线正在改的文件冲突。
- **只做投入小、马上见效的一半**，另一半等数字说话。
- **不做**：每一步的普查成本一直付下去。

## 决定

1. **目标形状**：`Sim` 只当三样东西——世界本身（就是 WORLD_API 背后那个对象，不另造世界对象，因为脚本、端口和测试里 `sim.bodies` 这类写法有几百处，改了换不来新能力）、部件的装配、跑局入口（`run` / `advance` / `step` / `report`）。其余按部件搬走：命令、帧格、生死与修改、战斗、玩家系统、视野、脚本状态、观测。AI 大脑只碰 WORLD_API 里它真用的那一小撮名字，所有写都走命令端口，读走观测和设置端口。
2. **第一期**（约 7 个会话）：
   - AI 大脑：加守卫限定它只碰那一小撮世界名字；读的漏口改走端口；写的漏口改走命令端口并删掉 `Peers`；建精炼厂送的免费矿车归生产规则；私有模型的回调集中成一张表。
   - `Sim`：先加守卫（每个包用到的 `Sim` 名字数只许减，中心棘轮加"字段数"）；再收掉单位命令、帧格、生死与修改三组只转手的方法。
   - 先后：两边都要改命令端口那个文件，一个做完另一个再做；AI 大脑删掉借用的"修改"要早于 `Sim` 收生死与修改那一步。
3. **第二期**（战斗、玩家系统、视野、脚本状态、观测五块搬家，AI 大脑拆文件）**现在不做**。第一期做完后量两件事再定：各线每一步花在读代码普查上的上下文降了多少；中心棘轮（方法数、字段数、`sim.py` 行数）降了多少。降得明显、而且又有线频繁去改那几块，才开第二期。
4. **每一步的规矩**同 0029：纯搬家，逐帧记录前后一字不差，不把行为改动带进同一个提交；每步同一个提交里调低中心棘轮、删掉对应的转手登记；做到哪一步停都不亏。

## 后果

- 第一期做完，新代码碰不到 `Sim` 的大部分方法；AI 大脑和 `Sim` 之间只剩端口。
- 第二期不做的那几块（战斗、玩家系统等）的状态仍挂在 `Sim` 上，改它们的线照旧要读 `sim.py` 那一段。
- 设计细节（每组接口的名字、迁移步骤和每步的验证）在私有仓库的重构开工包里，本 ADR 只记决定。
