# 0019 游戏逻辑层整体移植成 Python 模型，按层分期，每层用对拍验收

状态：accepted（2026-11-05）。取代 [0017](0017-engine-layers-and-map-page.md) 里"按摩擦大小一层层还原"的排序；产物和存放位置仍按 [0018](0018-engine-model-private-repo.md)。

## 背景

用户原话（2026-11-05）："碰到什么查什么可能不太可行，我们能整体重构成python代码吗？"；看过方案后："可以按这个顺序做"。

到 11-05 为止的还原是做关卡撞到哪查到哪：寻路较完整，脚本、地形、升级只有零散规则，战斗和 AI 是空白。每个新机制（A9 暗时无敌、A3 时停区）都要在测试台上试一到两轮才找到写法。

《将军·绝命时刻》的 GPL-3 源码（`RA3Modding/refs/CnC_Generals_Zero_Hour`）里，游戏逻辑约 16 万行 C++：物体和模块约 9.8 万，AI 和寻路约 2.9 万，脚本引擎约 2.1 万。红警3 中间隔着《中土之战》一代引擎，那一代没开源，所以越往物体模块层，和《将军》的差异越大，要靠反编译红警3 程序核对。

## 决定

1. **范围是游戏逻辑层**：脚本、物体和模块、武器伤害、寻路、AI。画面、声音、界面不移植。
2. **顺序**：脚本引擎 → 物体和模块框架 → 武器伤害 → AI（寻路已有）。物体模块按"新机制愿望单"加"原版战役和我们的 mod 用到的模块"排先后。愿望单首批是用户提的三样：空中的建筑、导弹、无人机。
3. **每层单独能用**：一层做完，推演器和地图检查就换用这层模型。
4. **每层用对拍验收**：同一个小场景，在模型里跑一遍，在测试台上跑一遍，比计数器读数。对不上的地方回程序里读。
5. **每层开工前过闸**：总控先把上一层的对拍结果和额度花费报给用户，用户定继续还是停。
6. **只做认知工具，不改游戏**：mod 仍是 INI/XML 加地图脚本，由原版游戏运行，玩家照常安装。模型不分发。新机制只能用原版已有的模块和脚本拼；模型的作用是把拼法从试错变成查表加推算。

## 否掉的方案

- **继续按需查**：最省，但规则一直零散，每个新机制都要从头试。
- **只做脚本和物体框架，战斗、AI 按需**：花费约一半，战斗和 AI 的问题会留着。
- **逐行还原红警3 程序，含画面和界面**：没有符号、编译时优化过，规模远超逻辑层，对做 mod 没有额外收益。

## 后果

- 引擎线会是长期占额度最多的线，关卡线因此变慢；推演和检查会因此更准。
- 移植代码是 GPL-3 衍生作品，按 0018 只放私有仓库。
- 想做原版引擎做不到的事，比如往游戏程序里注入新模块，是另一条路，要单独定（会影响玩家安装方式、联网和许可）。本条不包括。
