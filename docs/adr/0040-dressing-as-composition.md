# 0040 装扮是拼出来的：地方配方、交界处理、节点三种原语加成套布景，空地要有用途

**背景**：2026-11-27 用户看 A1 闸门三（`work/mapgen_probe/gate3-a1/`）。和原版海德堡并排看，差距不在三处取舍，在街区没有生活：楼之间是大片空场，崖顶像一条带子，路边没有灯、车、长椅。

回头看前一天的六轮设计师读图：每轮都是"看图、找到一处丑、往生成器加一条规则"。林缘种一圈树、货物只上硬码头、雪坡留雪、坡肩岩石融合、转角件。三轮独立复查反复抓到"打着通用旗号、其实只为一张图"的规则，194 一次净增 219 行。用户问能不能把"截图加意见"自动化；总控的判断是那只会把堆规则做得更快。

只读调查（`work/mapgen_probe/notes/scene-survey.md`）的数字：

- 现有美化规则 44 条：地方填充 12、交界处理 16、几何或玩法 16。前两类很多按用途名、套名、物件名写死。
- 原版库有 146 张图、34.4 万中立物件、41,029 个候选组。入库的成套布景只有 15 组，原因是人工复看时只挑了三个主题，不是数据不够。海德堡老城估计还能取 15–30 组。
- 交界和成片自然景一组也挖不到：现有挖法要求原样重复，还不看植被、崖和路。
- A1 约 57% 的可玩区没有任何设计关系要求，是摆剩下的空地。

EA 的说明书说没有布景的图"像竞技场，不像一个地方"。它的做法是先做一组满意的布景，再复制、粘贴、修改。

**决策**：

1. **装扮只用三种原语，外观写成数据。**
   - **地方配方**：一种用途的块内部铺什么。
   - **交界处理**：两种地方相接的边上铺什么，如临街、崖顶、岸、林缘、登陆滩。
   - **节点**：不是一条边能说清的点，如崖转角、坡口、路口、三种贴图碰头。

   代码只做三件事：往区域里铺布景、沿边铺一条、在节点放配件。哪种地方、哪种边、哪种节点用什么，写在数据表里，按套件组织。新的样子加数据，不加规则。
2. **布景从原版量。** 成组的从原版图里重复出现的组合挖，被改过的副本也算。交界处理按"物件相对于边的分布"统计，不要求原样重复。量来的数据留在本机 `work/`，公开仓库只放生成库的工具和数据表的格式（同 [ADR 0038](0038-agent-map-generator.md) 第 5 条）。
3. **空地要有用途。** 开阔地要么由设计关系要求（集结、展开基地、留视线、射界），要么被配方填上。"留空"是写在设计里的玩法决定，不是代码里的默认值。
4. **用户的口味攒进库里。** 闸门上的取舍落成"某套件某种地方或边用哪一款"，以后同套件的图都照用，不再每张图问一遍。
5. **看图评审放在这之后。** 自动截图、独立评审、自动修的循环，等修法主要是改数据时再搭。

**后果**：

- `experimental/mapgen/dressing.py` 先做一次不改行为的重构：现有参数搬进数据表，统一用途词表（现有设计写 `oldtown`、库里写 `老城`）。验收为六张图导出逐字节一致；做不到时退到物件集合一致、全部关系照样通过。
- 第一份新数据是 A1 的临街和 5–10 组海德堡老城布景，同时出一份"无主空地"报告。
- 风险：有的布景要特定地形（码头要硬岸）；节点的配件要另量；填满会吃掉玩法空间，所以第 3 条要先于"凡空地都填"落地；农庄、冰岛、雪地套件样本少，要借相近的套。
- 进度在 [plan.md](../plan.md) 地图工具行，执行细节在 [mapgen/design.md](../mapgen/design.md)。

**否掉的方案**：

- **继续"看图、加规则"，再把它自动化**：规则会越堆越多，复查一再抓到只为一张图服务的规则。
- **整片街区搬原版**：会被老玩家认出来，也对不上我们的布局（同 0038）。
- **按空地占比之类的指标调密度**：用户明确说过不要设一堆指标去对齐数字；空地留不留看用途。
