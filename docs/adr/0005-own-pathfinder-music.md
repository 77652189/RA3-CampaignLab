# 0005 自制配乐走原版的 Pathfinder 动态音乐，格式自己逆向

**背景**：用户 2026-10-25 要用新生成的音乐替换原版音乐，要求贴合剧情和情景，并保留原版"按战况（优势、劣势、交战……）自然过渡"的效果。原版的战况判断写在公开的 XML 里（`SageXML/PathMusic/`），但真正决定"怎么接、在哪里接"的曲谱图（`PathMusicMap`，'PFDx' 格式）和音轨（`.mus`）没有任何公开资料。SDK 也没附带原版的 `.mpf`、`.mus`、`.h`，所以原版音乐本来就没法用 SDK 重新编译。红3OL 团队说他们破解了、会开源，用户的判断是"代码开源还是不要抱多大希望，靠自己做出来的才是可靠的"。

**决策**（用户 2026-10-25 选的路线 B）：
- 保留原版的战况状态机和事件；曲谱图（`.mpf`）和音轨（`.mus`）自己生成。工具在 `experimental/music/`：`pfdx.py` 读写曲谱图，`mus.py` 写音轨。
- 注入方法和关卡 mod 一样：BinaryAssetBuilder 编出实例，拼进原版 static 流的副本，音轨作为同名 cdata 打进 mod 的 BIG（SDK mod 按 id 覆盖不生效，见 `experimental/campaign/splice_assets.py` 开头）。
- 验证不靠人耳：只录游戏进程的声音，再用原版音频指纹或我们的示踪音认出在播哪一段（`listen.py`、`tracer.py`、`bench_listen.py`）。

**后果**：段落、过渡、按变量分支都能由我们设计，切换由引擎按段落边界对齐。代价是要自己逆向并维护两个二进制格式。音频编码要么用引擎接受的现成编码（XAS），要么得自己写 EALayer3 编码器。

**否掉的方案**：
- 绕开 Pathfinder，用 `MUSIC_SET_TRACK` 放普通音乐轨，由地图脚本判断战况（路线 C）：风险最低，但只能淡入淡出，没有引擎帮忙按小节衔接。
- 保留原版曲谱图，只把每段音频换成等长的新音乐（路线 A）：新音乐会被原版 715 段的结构和长度绑死，而且全游戏的音乐要一起换。
- 等红3OL 开源：不可控。
