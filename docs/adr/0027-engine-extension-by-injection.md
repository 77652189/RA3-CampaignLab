# 0027 给本体加新的引擎功能：注入自己写的代码，起义时刻只作参考、独立实现

状态：accepted（2026-11-09）。和 [0026](0026-engine-first-retail-inventory.md) 并行：0026 管"本体已有的功能模拟器都对得上"，这条管"本体没有的功能我们自己加"。

## 背景

[uprising-gap.md](../engine/uprising-gap.md) 查清了起义时刻比本体多出来的东西：13 种模块，外加几张枚举表里多出的取值。其中扫射方式（横扫以外的竖扫、来回扫等）和"展开"变形，本体用现有模块凑不出来。社区的 mod 普遍卡在"只能横扫"。我们要做新单位，很可能需要这类新功能，甚至起义时刻也没有的功能。

用户原话（2026-11-09）："第一层的做法大概率会卡在只能横向扫射，不能竖向扫射的问题上，这是社区里常见的做法，如果我们要加新功能，大概率是要加新的引擎功能的，起义时刻的代码不能搬运，但可以参考它是怎么做的，我们独立实现"。

## 决定

1. **新功能靠往本体注入我们自己写的代码来加**。走测试台截图 shim（`experimental/testbench/capture_shim.cpp`，以 `d3d9.dll` 挂进游戏）同一条路，但功能代码单独成一个模块，不和测试台的 shim 混在一起。
2. **起义时刻的程序只作参考**：可以读它"怎么做"（数据结构、字段、流程），代码全部自己写，不从起义时刻的程序里拷贝机器码或照着反编译结果逐句翻译。参考笔记和地址按 [0017](0017-engine-layers-and-map-page.md) 只放 `work/re/`。
3. **先做可行性试探，再决定投入**。试探要回答四个问题：
   - 本体怎么注册、创建、更新一个模块，新模块类型能不能挂进去；
   - SDK 的 BinaryAssetBuilder 能不能编译带新模块的单位（扩展 schema）；
   - 一个最小的新模块（比如只打日志的空模块）能不能在本体里跑起来，并且不崩、不影响存档；
   - 玩家安装时要多装什么，能不能做到"装了 mod 就能用"。
   四个问题都答"能"，再挑第一个真功能（竖向扫射），给它写测试台对拍和模拟器实现，和 0026 的规矩一样。
4. **新功能也要进模拟器**：每个新模块在模拟器里有对应的实现和测试，不许"只在游戏里有"（[0024](0024-playable-simulator.md) 第 0 条）。

## 否掉的方案

- **只用本体现有模块凑**：横扫以外的扫射和展开变形凑不出来，社区的经验也是这样。
- **把起义时刻的代码搬过来**：那是 EA 的代码，搬过来再随 mod 发布有版权问题。
- **等引擎达标后再说**：用户要先知道"加新功能"这条路走不走得通，因为它决定新单位能设计到什么程度。试探本身不挡 0026 的进度，单独开一条线做。

## 后果

- 新开引擎扩展线（D），只做试探和之后的新模块；A、B、C 三条线照 0026 继续。
- 如果试探答不了"能"，就回到"用本体现有模块凑"，新单位设计按 [uprising-gap.md](../engine/uprising-gap.md) 的约束来。
