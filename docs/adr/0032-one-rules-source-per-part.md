# 0032 规则每块只留一份，按来源分仓库：实测推得的进公开内核，读程序得到的留私有

状态：accepted（2026-11-17）。定 [0031](0031-simulator-module-composition.md) 第 3 条。用户先说"公开仓库只放端口和测试吧，完全重写代价太大了"；看了两份实现逐部件对比后改定："可以，按表改，寻路细节用测试台重推"。

## 背景

[0018](0018-engine-model-private-repo.md) 定：照程序重写的算法放私有仓库，公开仓库只放实测行为和接口。逐部件对比（私有仓库 `work/re/sim_split/model_vs_sim.md`）量到：

- 物体、战斗、命令、玩家规则实际跑的是公开模拟器自己的一份，大多从 XML 和测试台读数推得；私有模型的物体部分（`ra3model/objects/`）运行时不加载，两份之间没有任何对照，已知至少两处不一致（带升级或状态条件的自动回血、潜行和反潜）。
- 公开模拟器从私有模型借的只有脚本引擎核心、遭遇战 AI、玩家代理三块，外加 XML 读取。
- 公开 `sim.py` 里约 100 行寻路细节（路径拉直、步兵列队、目的地落点）是照《将军》GPL 源码改写的，`simgarrison` 里约 100–150 行是读程序得到的细节。

## 决定

1. **物体、战斗、命令、玩家规则只留公开一份**，就是 0031 的模块组合内核。来源只许是 XML、测试台读数和行为说明，不许照程序或《将军》源码转写。
2. **脚本引擎核心、遭遇战 AI 留在私有仓库**，经 0031 的端口接进内核；没有私有模型时公开内核用自己的 Python 脚本循环兜底。
3. **玩家代理暂留私有**：它的打法是我们自己设计的，但用了 AI 的选目标、微操规则。等它只依赖公开内核的端口时再挪到公开仓库。
4. **私有模型的物体部分冻结，只当对照**：每搬一个模块进内核，就和它对比一次，对不上的上测试台判谁对。
5. **越线的部分用测试台重推**：寻路那约 100 行、`simgarrison` 读程序得到的那部分，改成照测试台读数写，测试期望取读数。
6. **一个进程里能同时跑几个世界**：每个世界的状态只在自己的实例里，不许有模块级的可变状态。这是给多战场攻坚（一个游戏本体加几个模拟器战场同时打）准备的，有测试守住。

## 否掉的方案

- **规则内核整个放私有仓库，公开只放端口和测试**：要把实际在跑、本可公开的约 1 万行搬进私有仓库，法律上没有好处；多战场以后要随 mod 发给玩家的正是这一块。
- **以私有模型为准**：它的物体部分没有寻路、碰撞、命令和玩家系统，换过去等于重写这些。
- **两份都留、同接口互相对照**：规则还是两份，各线还得两边改。

## 后果

- 多战场要发给玩家时，模拟器战场里的敌人不能用私有的遭遇战 AI，要换成我们自己设计的 AI；到多战场立项时再定。
- 0031 的模块接口、工厂、调度、端口和迁移顺序由重构线 R 设计。
