# 0003 内容线独立成仓库，共享资源加锁

**背景**：配音发布和新内容在同一个仓库、同一台机器上由两个会话并行推进。复盘时发现，真正的摩擦来自共享资源：同一个 git 仓库里提交互相带走暂存文件；一个没接限流的显卡任务占满显卡，让游戏测试卡死；游戏/测试台互相占用；两边共写一份 HANDOFF。单位和工具链反而是边做边长出来的，拆开会更费沟通。

**决策**（用户 2026-10-18 确认）：
- 配音与发布留在 RA3-ChineseVoice；新战役、新地图、新单位、引擎工具链、测试台拆成本仓库（公开）。两个仓库同放在 `Documents\RA3Modding\` 下。
- 共享资源放在 `RA3Modding\shared\`：`locks\bench.json` 独占锁，`locks\gpu-*.json` 显卡租约，`gpu_limit.json` 是限流的唯一来源；格式由两边各一份、内容一致的 `ra3voice/reslock.py` 定义。
- 短任务交给子 Agent，避免污染主对话；会话之间只在接口或共享资源变化时发消息。

**后果**：本仓库带着 `experimental/` 和所用的 4 个工具模块的历史；`run_bench.ps1` 自动拿测试台锁，`throttle.setup` 自动登记显卡租约。

**否掉的方案**：按配音 / 单位 / 地图 / 引擎拆成四条线——单位、地图和引擎的接口还在天天变，四方协调的成本比共享资源冲突更大。
