# 0038 地图由 agent 从设计文件生成：承诺、设计、原厂图元、地图四层，agent 只改设计

**背景**：2026-11-26 用户看 A1 第 7 版（`work/mappage/a1h7/`）。两个问题一起摆出来：

- **改一处很贵。** 山、路、楼都写在每关自己的生成脚本里（如 `work/mappage/a1h7/gen.py`），A1 有六百多行；检查也是每关手写的（`work/mappage/a1h7/check.py`），又是几百行。挪一下山的陡面，要改十几个数。页面上手改的地方，下次一生成就被冲掉。
- **质感差。** 同比例和原版海德堡并排看：原版一张图约 6000 个物件、170 多种；a1h7 只有 937 个、18 种。原版有路面件 500 多段、人行道和车道线贴花一两千个、树一千多棵。a1h7 这三样分别是 0、0、6，楼则是 756 个一模一样的占位方块。山是平滑曲线算出来的任意高度，原版的崖壁件贴不上，所以坡面露白盒。

当天又读到了 EA 留在游戏目录里的 WorldBuilder 说明书（清单见 [research/first-party.md](../research/first-party.md)），弄清了三件事：

- EA 的地形和美术件是按规格互相咬合的：崖壁件多数高约 70，坡道有标准长高比，水面和陆地有固定高度。
- 场景件是"做一个满意的，再复制粘贴改"。
- 目标是"有城市感的战场"，不是城市本身。

用户的目标（原话）："以后任何玩家想做自己的地图，只需要一句话提出需求，然后 agent 出一个地形草图用来快速验证，再根据草图直接出一个质量很高的地图"；"主要是由 agent 改"；"这一步关键在于怎么样把复杂多样的地形抽象成几个分层次的类"。

**决策**：

1. **四层，自上而下只单向生成。**
   - **承诺**：是哪种关、在哪、什么时间和气候、用原版哪一两套风格、剧情梗概。
   - **设计**：块、界、点、关系。
   - **原厂图元**：按 EA 规格量化的地形、崖壁件、坡道、一整块水面、按类按套刷的贴图、路面件、楼、布景和场景件、路点、区域、边界。
   - **地图**：.map 和给任务用的地图模块。

   下一层由上一层加原厂库和随机种子**确定地**展开：同样的输入永远出同一张图。
2. **agent 只改承诺和设计，不碰物件。** 要动某一件具体的东西，就在设计里写一条带编号的"修补"，重新展开时原样保留。几千次摆放是展开器的事，agent 只做几十个决定。
3. **设计用四个名词，可以递归。**
   - **块**：一块地或一片水，写它做什么用。
   - **界**：两块之间的边界，只写宽度、两侧高度、每一段谁能过（步兵、车辆、两栖、船）。崖、岸、墙、街、坡道、台阶、桥、门的样子都按两侧和谁能过推出来，不另写。
   - **点**：和玩法有关的位置。
   - **关系**：用固定句式写的意图。

   块可以再切成小块，规矩不变。所以草图和成图是同一份文件写到不同深度。唯一例外是"跨"：一座桥越过一整块地。
4. **原厂图元层按 EA 规格量化。** 高差界（崖、台阶、挡土墙）的高度取崖壁件的规格并贴上崖壁件；坡道照模具的长高比；水照原版约定。缓坡不量化。具体数值落地前上台核。
5. **细节取原版，不自己造。**
   - 路用原版路面件；
   - 楼、布景、地面贴图按风格成套取（SDK 里按地方分好的 36 套）；
   - 场景件取原版图里重复出现的组合。纯装饰的不超过 6 件。

   这些库从本机游戏和 SDK 文件现生成，不进公开仓库；公开的是生成库的工具。
6. **装扮按"门面"分配密度。** 玩家看得到、会经过的地方（主路两边、目标周围、开场镜头）做足，别处从简，物件总数守预算。场景小品（被弃的车、检查站这类和剧情绑在一起的）由 agent 放，量少。
7. **三道闸门：草图、布局锁定、成品。**
   - 布局锁定之前，玩法层（地形、过口、每个街块的主角楼，用真楼的占地）要通过检查和模拟器代玩；
   - 锁定之后的装扮不许改玩法：装扮前后比一遍寻路，路被堵死或变长超出容差就报错；
   - 锁定后要改布局，退回设计层重来。
8. **检查分五类，按成本分三档。**
   - 五类：结构、原厂规矩（说明书的硬规则，单人战役可以写一句理由豁免）、关系、像不像原版、装扮前后的玩法比对。
   - 三档：设计层上几秒、展开后几分钟、上台几十分钟。
   - 和台上实测冲突时以台上为准。
9. **取代 [ADR 0017](0017-engine-layers-and-map-page.md) 的第 4 条"图形化编辑器是长期目标"。** 不做给人拖的编辑器：人用的编辑器 EA 已经给了，主要改图的又是 agent。地图页改成查看页，看设计、检查结果和并排对照。`experimental/mappage/` 归新开的地图工具线。

**后果**：

- 每关不再写地图代码。新地形种类加在展开器里，所有地图共用。
- 现有的草图格式（[shell/sketch-format.md](../shell/sketch-format.md)）和 `experimental/mappage/sketch2map.py` 往下当原厂图元层到地图层这一段用，往原厂图元的规格上补。
- 质量落在展开器的规则和原厂库上，要一类类对照原版调。最难的是从"两侧和谁能过"推出好看的崖、岸、台阶。
- 布局阶段就要用真楼，所以"先占位、后换皮"不再允许。
- 流程和架构细节写在 [mapgen/design.md](../mapgen/design.md)，需求在 [requirements.md](../requirements.md)「地图工具」，进度在 [plan.md](../plan.md)。

**否掉的方案**：

- **每关写生成代码（a1h7 的做法）**：改一处要动十几个数；规则散在每关；换一张图重来一遍。
- **先做给人拖的图形编辑器**：主要改图的是 agent；人要拖的话 WorldBuilder 现成就有。
- **细节全靠自己写规则生成**：a1h7 就是结果，品味和种类都差太远。
- **整张复用原版图**：地点对不上剧情，老玩家一眼认出。
- **整片街区搬原版**：同样会被认出，又跟我们的布局对不上。
- **自由高度加"最后换皮"**：崖壁件贴不上，换皮又会改掉占地，之前跑过的检查等于白跑。
