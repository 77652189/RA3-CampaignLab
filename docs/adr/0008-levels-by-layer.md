# 0008 关卡按层批量产出：剧情流程 → 地图内容 → 摆放实现，每层全战役做完再下一层

**背景**：用户 2026-10-28 把关卡的设计问题分成三层：1 剧情和台词，一个沉浸、完整的游戏流程，让玩家知道自己要做什么、有代入感；2 按这些体验要求设计内容完整的地图；3 把建筑、单位摆进去，验证机制能不能实现。用户的判断："我们的问题主要出在 1 和 2 上面，但是我们一直在改进 3，所以怎么改都不合格。" 文档上看得出来：A4 样板（`docs/design/a4-redesign.md`）第 3 步的 30 条闸门几乎都是机制和节奏，没有一份写全简报、台词、任务目标原文的稿子，地图只写了地块用途、口子宽度、高台，没写地方本身是什么样。原因在工具：模拟器、编译器、测试台都只给第 3 层打分，1 和 2 只有用户能判断，又没有他能快速过目的产出，各线就往能自动打分的地方使劲。

**决策**（用户 2026-10-28 选 B："我们需要的是批量产生关卡，我们的设计目标是27关，一个一个精修能保证质量，但是问题也会被过多的人工辅助掩盖过去，我真正想做的是一个工作流"）：
- **三层，每层全战役做完、用户过了闸门，才做下一层**：
  1. **剧情与流程**：先定战役大纲里悬着的问题（结局、背叛、关卡地点和关名、自由号的说法）；再给每关写一份流程剧本：简报全文，每一段镜头给玩家看什么、谁说哪句台词（原文）、任务目标原文、玩家靠什么知道下一步做什么，胜利和失败的台词。
  2. **地图内容**：按流程剧本写每一段发生在什么地方：什么场所、地标、玩家第一眼看见什么、讲故事的布景、这一段的玩法要的地形；配一张标了各段位置的图。
  3. **摆放与机制**：策划案、编译、模拟器、测试台。
- **每层先出模板，再挑几关不同类型的给用户校准，然后批量产出**，用户按批审。
- **某一关在闸门上出了问题，修的是产出它的模板、准则或生成器，再重新产出受影响的关；不手工补那一关。** 手工补会把工作流的毛病盖住，第 27 关还会犯同样的错。
- **机器只查每层的完整和一致**（每段都有目标原文和提示、台词里的人名在角色表里、地图内容里的地点在地图上），好不好由用户判断。
- 第 3 层的工具（模拟器、编译器、测试台）在第 2 层过闸门前冻结，只修挡路的 bug。

**后果**：第一关按新流程能玩要等前两层全战役做完，比一关一关做晚得多；用户要一次读一批流程剧本，先用几关校准来减轻。已有 11 关粗版和 A4 的返工留着不动，到第 3 层时按定稿的前两层重新产出。这段时间产出的主要是策划线，关卡线和单位线基本停着，省额度。`docs/design/charter.md` 的 7 步工作流在每一层里照旧用，变的是跨关的顺序（先横后纵），以及第 1、2 层多出流程剧本和地图内容两样产出。

**否掉的方案**：
- 用 A4 当样板，一关一关走完三层再做下一关：单关质量有保证，但每关都靠人工把关，工作流本身的毛病被掩盖；27 关一关一关做也太慢。
- 维持原样，三层一起改：就是"怎么改都不合格"的现状。
