# 0016 每类问题收成一个出口、一条产物规则、一个只收紧的守卫；整改和修问题合做

**背景**：2026-11-03 的只读架构评审（[reviews/architecture-2026-11-03.md](../reviews/architecture-2026-11-03.md)）找到五个核心问题：打包层靠 import 时改别人的全局变量拼起来；检查跑不到 CampShell 上，还会改动被测的关卡；台词有多个出口；挂点、镜头、编组命令、资源摆法在源头上没有代码；编译器和机关互相 import，注册表手写。共同的根子是同一件事有好几个出口、规则没有强制，所以 [ADR 0015](0015-fix-error-classes-at-source.md) 要的"从源头修"没有地方落。用户否掉了"只做低风险止血"："A没办法解决全部五个问题吧"；看过完整方案后："可以，按推荐做"。

**决策**：
- **每类问题收成三样东西**：
  - 一个出口：台词、镜头、编组命令只能经编译上下文 `Ctx` 的 `say`、`camera`、`order` 产出；打包只能经 `build_mod(ModSpec)`；
  - 一条产物规则：在编出来的最终地图脚本上检查整类规则，对每一关和 CampShell 都生效；
  - 一个守卫测试：放在 `tests/test_architecture.py`，以现状为白名单，名单只删不加。名单删空，这一类才算解决。
- **验证按改动性质分三种**：
  - 纯重构要求构建指纹不变，即 A4 单关、CampShell、CampShellEn 的 `.big` 里每个文件的 sha1 相同；
  - 故意改行为的，要求产物规则全过，并对照模拟器的台词时间表；
  - 玩家体验交给独立验收者在 CampShell 上玩。
- **测试版只等于正式版加观测。** 检查和外壳一样往 ModSpec 里加东西。检查脚本只许用观测词表里的动作（计数器、旗子、计时、区域判断）。需要玩家动作的，用测试台去点。用脚本代行玩家操作的检查改叫"机关单测"，不算验收。
- **整改和修 I1～I9 合在一起做**：按类别从源头修本身就是整改，不先做一轮纯重构。
- **手写关 a8、j4 拿同一个 `Ctx`**，不改写成策划稿。等以后轮到这两关返工时再迁。
- **`parts.py` 按层拆成三份**：关卡数据归关卡线，规则检查（contract）归总控和验收，打包归外壳线。旧文件留作转手导出的空壳。
- **不做大爆炸**：c2～c18 不一次性重写，只让它们从清单取值、用完恢复；`experimental/` 也不改成可安装包。

**阶段**：
1. 第 0 阶段（总控）：指纹基线，拆 `parts.py`，现在就能加的守卫，归档探针。
2. 打包收口（外壳线），同时做断环、`Ctx`、各自注册（关卡线）。
3. 验收层：检查能叠在外壳上，加观测词表和"测试版只多观测"的守卫。
4. 关卡线做各出口（K1、K2、K5、K6）。
5. 关卡线做生成器（K4、K3、K7）。
6. 在 CampShell 上独立验收。

第 2 阶段做完设一道闸：如果守卫立住了，但还没修好一个问题，就停下来重新评估。

**后果**：
- 完成的判据：白名单全部删空、守卫收到最严，并且 A4 在 CampShell 上通过独立验收。
- 预计 12～17 轮线会话，多出来的主要是第 0～2 阶段，约 4～6 轮。
- 新写一种台词、镜头或命令，只能走出口；绕过出口的写法会被守卫拦下。

**否掉的方案**：
- 先只做低风险止血（单位改路径、归档探针，再加守卫）：治不了五个问题里的大部分。
- 先把整改做完再修问题：多 3～5 轮，而且这期间产品没有进展。
- 把 a8、j4 改写成策划稿：等于重写两关，眼下没有必要。
- 一次性重写打包链：大爆炸，评审也不建议。
