# 0025 亲手试玩放在游戏里（带跳阶段、快进、跳过场），用试玩录像检验模拟器对齐

状态：accepted（2026-11-08）。取代 [0024](0024-playable-simulator.md) 第 4 条"第一轮玩法试玩在模拟器里做"；0024 其余各条（对齐优先、修改同步、模拟器界面不改规则）不变。

## 背景

0024 把模拟器做成了能玩的界面，用户第一次打开就遇到地图上下颠倒、语音重叠。两处都是界面外壳的问题，但说明了：在模拟器里玩，玩到的是"近似的游戏"，出了问题还要先分清是关卡还是模拟器。模拟器只能逼近游戏、做不到逐帧一样（寻路挤位、散布、AI 随机）。

用户 2026-11-08 同意"试玩放在游戏里更合理"，并问：跳阶段怎么和模拟器保持一致（玩家会多造兵、损失单位）；不试玩怎么知道模拟器对齐了。

## 决定

1. **亲手试玩在游戏里**：试玩版 mod 加三个开发开关：跳到第 N 阶段、快进（测试台的变速垫片）、跳过场；正式版没有（[0016](0016-one-outlet-per-class.md)）。模拟器界面留给看自动跑的局和查问题。
2. **跳阶段读标准开局，不复刻玩家过程**：每关每阶段一份"阶段存档点清单"（玩家兵力与位置、钱、已完成目标和已亮的旗、敌方剩余，可带变体），从全程脚本在模拟器里跑到该阶段的状态导出；游戏和模拟器读同一份。每关交付前仍要在游戏里从头完整打一遍。
3. **用试玩录像检验对齐**：红警3录像只存命令。同一个录像在测试台的游戏里回放、读兵力和目标时间，再把命令喂给模拟器跑，按时间点比；差 15% 以上停下归因。每次试玩自动多一局对照局（[0023](0023-simulator-as-daily-verifier.md) 第 1 条）。
4. **表现类问题按类自动查**：朝向（模拟器画面与 `cnv_map` 共用 `maprender.SCREEN_Y`）、台词与字幕重叠（游戏里静音录音加读字幕，和模拟器台词时间线比）；第一次出现的一类靠人发现，之后由检查守住（[0015](0015-fix-error-classes-at-source.md)）。

## 否掉的方案

- **继续在模拟器里试玩**：手感和细节不准，问题归因多一层。
- **跳阶段时把玩家前面的打法补算出来**：玩家过程每次不同，两边起点对不上；标准开局才能保证一致。

## 后果

- 引擎 A：录像解码和"游戏回放 vs 模拟器"比对工具（`experimental/replay/`）。
- 关卡线：阶段存档点清单的格式和 A4 的第一份；游戏里的表现检查。
- 模拟器界面线：试玩版的三个开关，界面的跳阶段改读同一份清单。
