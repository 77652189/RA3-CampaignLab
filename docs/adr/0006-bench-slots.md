# 0006 测试台同时开几局：每局关掉自己的单开互斥锁，按槽位加锁

**背景**：几条线和总控的验收都排队用一个测试台，一次全套验收要一两个小时；用户自己玩时测试台也得停。用户 2026-10-27 问能不能不走原版加 mod、自己写引擎或启动器。查下来，测试台早就不经过 Steam 和启动器：它直接启动自己那份游戏副本（`work/testbench/RA3`），向自己的窗口发消息、在游戏进程里截帧，不抢鼠标键盘。真正卡住的是游戏只许开一份：测试台实测，第二份启动一秒内自己退出；它认的是一个命名互斥锁 `41DAF790-16F5-4881-8754-59FD8CF3B8D2`，只在第一份里关掉这一个，两份就能并排跑，各约 118 帧每秒。

**决策**（用户 2026-10-27 同意试同时开几局）：
- 测试台的每局游戏起来后，在自己进程里关掉这个互斥锁，下一局（包括用户自己开的游戏）就能启动。只动测试台自己启动的进程；用户开的游戏不碰，它开着时测试台照旧不启动。
- 测试台分槽位，`RA3_BENCH_SLOTS` 设几局（默认 2）。第 1 槽的锁还叫 `shared\locks\bench.json`，老工具照旧等它；之后是 `bench-2.json`……每槽有自己的截帧文件夹（截帧垫片的 `CNV_SHOT_DIR`）。锁里记着游戏进程号和 mod，用来分清哪局是测试台的、哪局是用户的。
- 编 mod 时只有两种情况才改放 `work/staging`：用户的游戏开着（它可能开着任何 mod），或者某局测试台游戏正开着同名的 mod。别的测试台游戏开着不影响编译。
- 代码：`experimental/testbench/slots.py`，`harness.Session.start` / `_launch` / `stop`，`experimental/cnv/parts.py` 的 `mod_busy`。

**后果**：几条线可以同时跑检查，验收按槽位数成倍变快；测试台开着时用户也能开游戏。代价是显卡同时带几局；几局共用 `Documents\Red Alert 3` 下的设置和 Mods 文件夹，所以同一个 mod 名同一时间只能有一局用（mod 名本来就按检查区分）。还在用老代码的会话（会话重启前的 ra3bench MCP、`run_bench.ps1`、各个 `make_*.py`）看见任何游戏开着就不启动，只会更保守，不会冲突。

**否掉的方案**：
- 自己写引擎（类似开源的 OpenSAGE）：多年的工作量，而且我们做的是跑在原版游戏里的 mod，在自写引擎里过了检查不能证明原版里也对。
- 在虚拟机里各开一份：这台电脑是 Windows 家庭版，没有 Hyper-V / 沙盒，虚拟机里也没有像样的 Direct3D 9 显卡加速。
- 去改游戏可执行文件、拿掉单开检查：改的是二进制，换版本就得重找；关掉进程里的互斥锁效果一样，而且不改任何文件。
