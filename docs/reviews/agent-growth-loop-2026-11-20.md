# 根因分析：为什么 agent 干活会越做越慢（2026-11-20）

用户 11-20："这些方法还是治标不治本，我在几个月前就遇到了一模一样的问题，最后就变成了做一步停一步。"
同样的问题在两个项目里都出现，说明病根不在某个项目，而在我们用 agent 干活的方式。

## 现象（11-19 中午到 11-20 下午）

- 代码一天净增约 1.3 万行（测试 +9800），Python 共约 18.6 万行；其中模拟器本体约 2.9 万，验收脚本 + 测试约 10 万。
- 每条线清空后，开工前就有约 5.5 万固定上下文（工具说明、技能、记忆、规矩）；15 万的交接线只够做半步。
- 8 轮复查报约 30 个 P2，三分之一是父版就有的；三条线常常一个会话只修一两项。
- 每发现一个问题，总控的反应都是"再加一条"：AGENTS.md 加规矩、巡检加一项、提议加模板。

## 循环

```
出问题 ──> 用"加东西"修（规矩、测试、复查、文档、守卫）
  ^                                   |
  |                                   v
犯错变多 <── 能干活的注意力变少 <── 每次开工要读的东西变多
```

这个循环能自己转起来，有三个原因：

1. **agent 天生偏向"加"。** 每个会话从零开始、看不到全局，解决问题的默认动作是再写一点；删东西要先懂全局，它做不到，也没人要求。
2. **系统里只有"加"这一个动作。** 规矩、测试、交接、文档都只增不减，没有哪个环节负责"减"、对整体大小负责。
3. **代价推给未来。** 多写的每一行、每条规矩，当下的会话感觉不到；由之后每个要读它的会话付。

结果是人成了唯一的"减法器"和唯一的全局视角，只能做一步、停一步、看一眼。

## 区分两种复杂度

- **本质复杂度**：游戏本身的运行逻辑，包括武器和弹头效果、移动寻路、生产、脚本、AI，以及它们之间的先后顺序。这部分必须完整理解，**不缩范围、不走捷径**（用户 11-20："从最困难的事情开始做，后面就会越做越简单……必须确保我们理解整个游戏的运行逻辑，每个部分负责什么"）。约 2.9 万行模拟器加上私有模型，大体在这里。
- **偶然复杂度**：我们怎么把这些逻辑写下来、怎么验证、怎么协调多个 agent，比如验收脚本的写法、测试的堆法、规矩和交接的写法、复查的轮数。**循环里转的全是这一种。**

根治的意思是：本质复杂度照单全收；偶然复杂度要靠结构压住，不能靠加规矩压。

## 两个根本方向

### 1. 把规矩从文字搬进结构：让错的做法做不出来，而不是"禁止去做"

判据：**一条规矩如果要靠文字告诉每个会话，就说明设计上缺了一块。** 好的结构会限定 agent 产出的形状，它想多写也没地方写。

| 地方 | 现在靠什么 | 结构上该是什么 |
|---|---|---|
| 模拟器加规则 | 改中心文件 + 文字分层规矩 | 物体 = 模块组合（ADR 0031）：加一条规则 = 一个模块类 + 一条模块测试，中心文件不动 |
| 对拍一项 | 一份 100 行脚本 + 一条整局测试 | 读数是数据（ADR 0035）：加一项 = 一行数据，一个通用跑器负责跑 |
| 派活 / brief | 自由文字，靠总控记得写全 | 有固定字段的格式（目标、完成标准、预算、不做什么），由工具解析、缺项就拒 |
| 测试大小 | 文字"测试写最少" | 族收尾时做变异检验：删掉一条后变异仍全红，就说明它是多余的，删掉 |

我们已经定了 0031 和 0035，但都在半路。**过渡期最糟**：新旧两套同时存在，转调、特征测试、两份规则都是双份的。所以第一要务是把这次搬迁做完，中途不开新战线。

### 2. 让"减"和"加"有同等地位

- **固定上下文设硬预算**：每次开工都要读的东西（AGENTS、CLAUDE、记忆、交接、技能、MCP 工具）有总上限，由脚本量，超了就红。
- **一进一出**：想加一条规矩，同时删掉或合并一条；想加一个守卫，先看能不能并进已有的。
- **族收尾固定做减法**：删转调、删被覆盖的特征测试、整批修 P3。这是"减"的固定时点。

## 不做的

- **缩小模拟器的精度和范围。** 这样能省下偶然复杂度，但代价是看不懂游戏，后面的修改都成了空中楼阁（用户 11-20 否决）。
- **再加规矩、模板、巡检项来压问题。** 这正是循环本身。

## 下一步

1. 这轮搬迁做完前：不加新规矩；已经定的"族收尾做减法 + 巡检记账"照做。
2. 搬迁做完后，排在 0035 读数迁移之前或同时做：
   - 普查现在所有的文字规矩（AGENTS、CLAUDE、各交接常设节、记忆），逐条归类：能搬进结构的、要保留的、能删的；
   - 给固定上下文做一个量法和预算；
   - 派活和 brief 改成有字段的格式，由工具校验。
