# 地图工具：流程和架构

决策和否掉的方案见 [ADR 0038](../adr/0038-agent-map-generator.md)、[0039](../adr/0039-city-roads-first.md)，目标和验收见 [requirements.md](../requirements.md)「地图工具」，进度见 [plan.md](../plan.md)。本文写各层装什么、谁写、彼此不许越什么界，以及一张图从一句话到成品走哪几步。设计语言（地图该怎么摆才好玩）在 `.claude/skills/map-design/`，EA 的规矩在 [research/first-party.md](../research/first-party.md)。

## 一、四层

| 层 | 装什么 | 谁写 | 量级 |
|---|---|---|---|
| ① 承诺 | 关的种类（建基地 / 渗透 / 英雄）、地点、时间和气候、用原版哪一两套风格、剧情梗概、硬约束 | agent（从一句话或关卡卡片） | 十来行 |
| ② 设计 | 路（城区）、块、界、点、关系，加状态、门面、场景小品、修补 | agent | 几十到一两百行 |
| ③ 原厂图元 | 量化的地形、崖壁件、坡道、水面、贴图、路面件、楼、布景、场景件、路点、区域、边界 | 展开器 | 几千件 |
| ④ 地图 | .map、地图模块（`SITES`、边界、路径，给任务用） | 现有写出工具 | — |

只许从上往下生成。③ 由 ② 加原厂库和随机种子确定地算出，同样的输入永远出同一张图。人和 agent 都不直接改 ③、④。

## 二、设计层

### 五个名词

- **路**（只在城区用，[ADR 0039](../adr/0039-city-roads-first.md)）：一条带宽度档（巷、街、大道）的线，可以弯、可以斜，连成路网，交叉处自动成路口。城区先写路网，块按路围出来的形状切。
- **块**：一块地或一片水。写它的**用途**（老城、住宅、郊区、工业、码头、公园、广场、林子、农田、野地、水……）和**主角**（这一块里最主要的东西：驻军楼、院落、停车场、空地等，见第四节）。块可以再切成小块，规矩一样。
- **界**：两块之间的边界。只写三样：
  - 宽度；
  - 两侧各多高；
  - 沿线每一段谁能过（步兵 / 车辆 / 两栖 / 船；飞机不受地形影响）。

  长相由展开器推出来：

  | 两侧 | 谁能过 | 长成 |
  |---|---|---|
  | 陆，同高 | 都能 | 野外：开阔地连着；城区的街由"路"写，不由界推 |
  | 陆，同高 | 都不能 | 墙或一排楼（一侧是据点就长成墙） |
  | 陆，不同高 | 都能 | 坡道或缓坡 |
  | 陆，不同高 | 只步兵 | 台阶、挡土墙 |
  | 陆，不同高 | 都不能 | 崖 |
  | 陆和水 | 两栖能 | 沙滩 |
  | 陆和水 | 不能 | 堤岸、码头、崖岸（看陆侧用途） |
  | 水和水，不同高 | 船不能 | 瀑布、坝 |

  "开一个口子" = 把某一段写成能过。路碰到界自动配口子：碰到崖就开坡道，碰到水就架桥；碰到写明"都不能过"的那一段报错，不偷偷推翻。
- **点**：出生点、地点（写要多大的平地）、矿、科技建筑、敌营、出兵点、目标、地标。
- **关系**：设计意图，用固定句式写（第六节），每关自己写。

**唯一的例外是"跨"**：一座桥或高架越过一整块地，连接两块不相邻的地。

### 另外几样

- **状态**：同一张图在不同阶段换掉某些界的"谁能过"、某块水的高度、可玩区边界（炸桥、破墙、水位升降、开新区域）。
- **门面**：哪些地方玩家看得到、会经过（主路、目标周围、开场镜头）。装扮的密度按离门面远近分配。
- **场景小品**：和这一关剧情绑在一起的布置（被弃的车堵路口、检查站、塌了一半的楼），量少，agent 自己放。
- **修补**：对展开结果里某一件具体东西的改动（挪开、删掉、换掉），按展开器给的稳定编号写，重新展开时原样保留。

### 草图和成图是同一份文件

- 只写第一级（主路、大块、硬隔断、三个关键点、关系）就是**草图**，已经能在路、块和界连成的网上跑检查。
- 往下切到街块、给每块定主角，就是**布局**。
- 再加门面、小品、修补，就是**成品**的全部输入。

## 三、原厂图元层

展开器的输出只用 EA 策划在 WorldBuilder 里用的那几种原件，规格跟着原版美术走。标"实测"的已上台核过（11-26 探针，结论在 `work/mapgen_probe/findings.md`），其余出自说明书，落地前要核。

- **地形**：平地和缓坡照设计层的高度自然过渡。高差界按档取：**一档 = .map 原始高度 1792 = 世界 70 单位**（实测；原版 27 关的平台全落在整档上，陆地从 3 档起）。崖面贴同风格的崖壁件（实测不可跨），按套查表摆：海德堡普通件间距 100、原点向高侧 15；起义时刻 `_GRID` 件按 30 网格，直段间距 120、原点向高侧 30。崖面刷崖专用贴图，崖下面刷透明贴图。
- **坡道**：一档高配长 **180**（实测游戏里 125 起就能走；180 是过现行坡度校验的对齐取值）。
- **水**：一整块水面，水面和陆地起始高度照原版约定，海底留够潜艇的深度。
- **贴图**：每块按"风格套 × 类"（`Terrain.xml` 的 Class）选一张底图、少量点缀；融合自动做，不叠三层。
- **路**：照设计层的路网铺，原版是三层混用（11-27 探针，实测）：带模型的街道件出沥青、路缘、车道线、斑马线和停车场（直段、直角、S 弯、丁字、十字各有件）；编辑器画路工具的线段出人行道、砖边、土路和细标线；Road 类底图垫在下面。宽度按件选：巷 60–70、街 85–100、分隔大道 170–175。我们的写出工具能原样写回这几层；街道件下面要关掉地表显示位。
- **物件**：楼、布景、场景件都从选定风格套里取。
- **任务接口**：路点、路径、触发区域、按状态分的可玩区边界，名字从设计层的点和状态来。

## 四、展开器

### 主角先定，装扮后放

布局阶段每个街块先放主角，用**真楼的占地**，玩法检查在这一步就算准。装扮不许挪主角。

### 三种方式

| 方式 | 摆什么 | 依据 |
|---|---|---|
| 沿线 | 路面件和贴花、路灯、行道树、停着的车；崖边的崖壁件、崖脚的石头；岸边的码头、堤、步道 | 由界生成，间距取原版统计 |
| 成片 | 林子、草、灌木、石头 | 按块的用途；原版的密度和成簇方式；"40 棵树就是一片林子" |
| 成组 | 主角周围的配角（院子、停车场、长椅），以及装饰场景件 | 原版图里重复出现的组合；纯装饰不超过 6 件 |

密度按门面分配，物件总数守预算。随机的地方都用设计里写的种子，想换样子就换某一块的种子。

## 五、原厂库

从本机游戏和 SDK 文件现生成，带版本号，不进公开仓库；公开仓库里只有生成它们的工具。

| 库 | 来源 | 用途 |
|---|---|---|
| 风格套 | SDK `SageXML\Civilian\<地方>_<前缀>\`、`Terrain\Terrain.xml` | 每套有哪些楼、布景、贴图（按类） |
| 路面件和崖壁件规格 | 原版和起义时刻图里的摆法（含 `_GRID` 版） | 接口位置、长度、弯道半径、崖高 |
| 场景件 | 原版图里"同样几种物件、同样相对位置、出现不止一次"的组合 | 成组展开 |
| 挡谁表 | E 线 E266 的结论 | 装扮前后寻路比对、零件挑选 |
| 密度统计 | `experimental/campaign/mapstudy.py` 对原版图的量 | 沿线间距、成片密度、"像不像原版" |

## 六、检查

| 类 | 查什么 | 跑在哪 |
|---|---|---|
| 结构 | 块被路或界围合、路网连通不悬空、界两侧对得上、每道崖至少一个口子（除非写明）、点落在块里、修补指向的编号还在 | 设计层 |
| 原厂规矩 | 基地至少三个入口（两条直路一条绕路）、卡口至少 200 宽且每个基地最多一个、桥不是唯一的路、基地区平、坡不陡到打不上去、楼之间留够寻路空间、大物件不挡镜头、触发区重叠不超过 5 个、物件总数 | 设计层（能算的先算）和图元层；单人战役可在设计里写一句理由豁免 |
| 关系 | 这一关的意图，固定句式：**谁先到**（A 到 X 比 B 近至少多少）、**罩住**（X 的射程或视野罩住某段路多少）、**通不通**（某兵种从 A 能 / 不能到 B，只能经过 C）、**绕多远**（经过 C 比直走多不超过多少）、**看得见**（从 A 看不见 B）、**放得下**（X 下面有多大平地） | 草图上用块和界的网粗算；展开后在格子上细算 |
| 像不像原版 | 逐块的密度、空地比例、成簇方式、同一零件附近重复几次；同比例俯视和固定镜头截图，与同风格原版并排 | 图元层、上台 |
| 玩法比对 | 装扮前后寻路：哪条路变长、哪个口被堵 | 装扮之后 |

按成本分三档，便宜的先跑：设计层上几秒（每改一次都跑），展开后几分钟（加模拟器代玩），上台几十分钟（只在成品前）。和台上实测冲突时以台上为准，然后回来改规则。

## 七、流程

| 步 | 做什么 | 层 | 谁 | 之后 |
|---|---|---|---|---|
| 0 | 一句话变成卡：戏、剧情事实、硬约束、关的种类 | — | agent | |
| 1 | 写承诺 | ① | agent | |
| 2 | 写关系 | ② | agent | |
| 3 | 草图：主路、第一级的块、界、点 | ② | agent | 设计层检查 → **闸门一：看草图和红绿清单** |
| 4 | 布局：切到街块、定主角（真楼占地）、定过口 | ② | agent | 展开玩法部分（地形、水、路、主角）→ 结构、原厂规矩、关系检查 + 模拟器代玩 → **闸门二：布局锁定** |
| 5 | 装扮：门面、场景小品、种子 | ② | agent | 展开沿线、成片、成组 → 像不像原版、玩法比对 |
| 6 | 地表和环境：贴图按风格套和类刷，光照照同风格原版图 | ③ | 展开器 | |
| 7 | 导出：地图模块、任务接口、按状态分的边界 | ④ | 现有工具 | `contract` 检查任务和地图对得上 |
| 8 | 上台：固定镜头截图并排原版、帧率；能的话用 WorldBuilder 打开看 | — | 测试台 | **闸门三：成品** |

锁定之后要改布局，就退回第 4 步重来。装扮阶段改出的玩法变化会被玩法比对拦下来。

### agent 的循环

在第 3、4、5 步里，agent 按"写决定 → 展开 → 读诊断 → 改决定"转，直到检查全过。诊断给的是 agent 读得懂的东西（逐块的数、玩法比对、标了问题的图），不给几千个物件。每种毛病对应一个可以调的决定：

- 太空：换大一号的主角或加院子；
- 太挤：缩小主角或拆块；
- 路被堵：换掉挡路的零件，或写一条修补；
- 看着重复：换种子或镜像；
- 视野不够：改界两侧的高度档。

## 八、和现有代码的接法

- `experimental/mappage/sketch2map.py` 和它的草图格式（[shell/sketch-format.md](../shell/sketch-format.md)）往下当"③ → ④"这一段用，按原厂图元的规格扩充，不另起一套写出工具。
- `experimental/mappage/cityblocks.py`（沿街排楼）、`experimental/campaign/platprops.py`（布景）是展开器的前身，收拢成按用途通用的规则后去掉每关各写一份的做法。
- `garrison_cover.py`、`attack_routes.py`、`experimental/campaign/maprender.py`、`mapstudy.py` 直接当检查和诊断的零件用。
- 地图页（`serve.py`、`sketch.html`）改成查看页：画设计层、叠检查结果、并排原版对照。

## 九、不许

- **agent 不直接改 ③、④。** 要动具体东西写修补。原因：一重新展开手改的就丢；几千个物件读不进上下文。
- **每关不写地图代码。** 地图是数据；新地形种类加在展开器里，所有地图共用。
- **高差界不出规格外的高度**，崖不露白盒；缓坡不受这条限制。
- **布局阶段不用占位方块**，主角用真楼的占地。
- **装扮不改玩法**：玩法比对超出容差就是错误，不是提醒。
- **原厂库和从原版拆出的数据不进公开仓库。**
- **检查只读不写。** 任务只用地图导出的名字（已有规则，见 [architecture.md](../architecture.md)「不许怎么做」第一条）。

## 十、还没定的

11-26 四项探针已答：编辑器能打开（按编辑器自己的单层包法另写一份，带 `GlobalVersion`）；崖高、崖壁件摆法、坡长见第三节；原版图里挖出 15 组可用场景件；老城切片闭环通过、游戏里能加载。还没答的：

- 画路工具的弯道半径（街道件的已量）；
- 两片不同高度的水、同局改水位能不能做（第一版只出静态的各状态边界和名字，动态由关卡脚本兑现）；
- 像不像原版只用指标定位差异，观感由用户在闸门三看并排截图。
