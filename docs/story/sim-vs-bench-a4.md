# A4 的测试台检查，模拟器能替代多少（2026-11-06，关卡线）

用户 11-06："等引擎线做完再对接吧，试试关卡线能不能只靠模拟器制作，不依赖测试台"。这一轮没开测试台（没调 `cnv_check`、`bench_*`、`build.py --check`），A4 地形大改（K7 / I8）后还没跑的 7 项检查，逐项用模拟器重做了一遍。

**结论一句话**：7 项里 **2 项能完全替代**（detour、smoke）、**1 项能替代但墙的消失靠脚本代劳**（queue）、**3 项只能替代一部分**（melt、smash、win）、**1 项不能**（derrick 的"占下来、钱涨"是引擎的事）。能替代的部分读数和测试台以前的读数对得上（见表）。模拟器版没有一项靠"看着像"过关：每项都做了变异（玩家什么都不做就必须红），`tests/test_simbench.py` 守着。

## 怎么跑

```
python -I -X utf8 experimental/cnv/simbench.py            # 7 项全跑，约 1 分钟；也可以只写检查名：simbench.py detour smoke
python -m pytest -q tests/test_simbench.py                 # 6 项过 + 3 个变异 + 1 条"读不了的读数写 SKIP 不写 PASS"
```

`simbench.py` 是新文件，没动 `sim.py`。做的事只有三样：
1. 照检查自己的 `build.resolve('a4', 检查名)` 造任务，交给 `sim.Sim`；
2. 玩家那一份写成模拟器的剧本：工兵的冰技能模拟器只记一笔不起作用（`ALIGN['special power']`），所以脚本里在"下令时间 + 9 秒"用 `造` 把墙放在冰点上，墙的寿命到了用 `删除` 拿走（9 秒取自 `checks/a4.py` 的 `BUILD` 注释：下令后约 9 秒墙立起来）；
3. **对时间**：测试台的第一帧是开场过场结束那一刻，模拟器的钟从任务开始算，开场过场占 80 秒。所以读数整体前移 80 秒（取日志里"过场：交还控制"的时刻），再用检查自己写的期望来判。

模拟器读不了的读数（没有那条规则）列为 `SKIP`，**不算 PASS**。这一条是踩出来的：smash 的"目标墙血量 < 100"，模拟器里没人设引用，血量读 0，对 `< 100` 恒真，第一次跑出了假 PASS。

另外两点这轮**没有**问模拟器、也不能问：
- **房子行挡不挡得住步兵**（上轮遗留第 4 条）：模拟器按占地盒算挡路，游戏的寻路怎么对待房子是引擎的事。detour / queue 的读数里兵能不能走到口子也是同一个假设，所以这两项的"能"是针对**接线**说的。
- **`place` / `placem`（玩家点击放墙，游戏的放置规则）**：不在这 7 项里，上轮已在测试台过；它测的正是模拟器"记一笔不起作用"的那一块，永远要测试台，除非引擎模型补上 R5 并量清规则。

### smash 的两处出入

1. **鬼王上岸的时刻**：测试台 s58，模拟器 s75，差 17 秒。模拟器里运输船比测试台慢（或"到岸"的判定区不一样），两边的船速没对上；这是该给引擎线的新条目（R7：运输船的移动速度 / 到岸判定）。
2. **鬼王不砸墙**（真问题，不是模拟器的事）：墙立住（冰墙 1）、鬼王上岸（读数 1）、脚本也已经把"最近的墙"指到了墙上（血量读数 100，不是没指到时的 0），但鬼王在上岸点（`CNV A4 Shore`，4120, 2900）站着不动，墙（`ice L3`，3575, 2770）在它西边约 550 处，墙活到寿命都没被碰。10-31 的 PASS 是 100→76→65→53，所以是 K7 / I8 改地形之后才出的。**没查清原因**，我的怀疑（没证实）是上岸点到那面墙之间现在没有路（运河、砖墙、房子行），鬼王接到攻击令却找不到路，原地不动。手动看到的：上岸点西边是一条水道，水里是龙雕像，再往西隔着砖墙才是冰墙。
   - **（上面的怀疑是错的，11-07 第二十九个会话查清了）**：`sim.py` 的寻路问"上岸点到 `ice L3`"有路（地面 15 点，约 930 长，直线 560，要绕：上岸点 → 过运河上的桥 → 向西 → 进砖墙院子）。测试台上看，鬼王上岸后 5 秒就走到桥上，**停在桥中间，离墙约 345**，不再动，也不开火；它的炮程在 270 到 345 之间。
   - **真因**：`horn.py` 的 `smashes` 脚本（`once=False`）**每一帧**都给鬼王重下一次"攻击这面墙"的令。墙立起来时鬼王还得走一段才进炮程的话，每帧重下令让它原地不动（墙立起来那一刻它停在哪就停在哪）。三次测试台对比：墙在鬼王上岸前就立着（原检查）→ 血量一直 100；墙在上岸后 3 秒立（`ICE_LATE=2`）→ 一直 100；墙在上岸后 11 秒立（鬼王已走到桥西、本来就在炮程内）→ 能砸，血量 88→76→65→41→30→18→6。10-31 的 PASS 是旧地形上岸点离墙近、不用走。
   - **修**：`devices/horn.py` `ghost_scripts`：每个鬼王对每面墙**只下一次令**（新旗 `CNV_<tag>_Hit_<n>_<j>`，下令时置 1，"墙没了"那条脚本 `Ghost dropped` 把它们清 0，下一面墙重新下令）。原检查不改（`ICE_LATE=-2`，墙先立着）在测试台 PASS：血量 100→76→53→41→18→6。
   - 这个 bug 的本质：**对同一目标每帧重下一次移动 / 攻击令，单位走不动**。别的设备里有 `once=False` 的 `ctx.order`（`hunts` 每帧下令却能动，因为那时单位本来在走；没有改，没证据）。该写进经验的是：持续条件下的命令要用旗做成一次性。

## 同一类毛病的扫描（2026-11-07，ADR 0015 从源头修）

问的是"脚本每帧给单位重下移动 / 攻击令"还有没有别处。方法：对 `build.MISSIONS` 里每个任务和每个检查合并后的脚本，找 `once=False` 且动作里有整队命令（`TEAM_ATTACK_NAMED`、`MOVE_TEAM_TO`、`ATTACK_MOVE_TEAM_TO`、`TEAM_GUARD_AREA`、`TEAM_HUNT`）的脚本。结果 15 族：

| 族 | 目标 | 测试台上的证据 | 处理 |
| --- | --- | --- | --- |
| `King n-j smashes`（a4） | 引用（`UNITRef`，SET_REF 选出来的墙） | **会卡住**（本节上面） | 已改成只下一次（`Hit` 旗） |
| `King n-j hunts at t`、`Convoy target t at t`、`Chase`、`Held`（a4 / a4_before / a8 的 assault） | 有名字的卡车或区域 | 鬼王 hunts 时从上岸点走过桥（s58→s63）；车队咬住卡车的检查（win）PASS | **没改**：每帧下令在这些上走得动，改了会动已经验过的车队行为，没有反例就不动 |
| `Roll`、`armoured to`、`cryo to`（a4、ally、j4、s2、sapporo） | 路点（移动） | 车队沿街走到港口（win PASS，三辆车 s438～s468） | **没改**，同上 |
| `Test - ...`（检查自己的） | — | — | 不管 |

只有"目标是引用"的一族出了事，所以守卫也只管这一类：`contract.ref_orders_once`（G16，并进 `contract.check`，`test_every_build_keeps_the_contract` 每个任务都跑）——`once=False` 的脚本对 `UNITRef…` 下整队命令，必须自己测一面旗（`FLAG f 0`）并置它（`SET_FLAG f 1`），否则红。`tests/test_engine_rules.py::test_g16_*` 两条：合成脚本的变异（每帧下令红、只测不置红、置了过、有名字的目标不管、`Test` 不管），和 a4 的真实脚本去掉旗变红。

我**没有**证明"每帧重下令一律会卡"。机制猜测（没验证）：目标是引用 / 墙这种要绕路的，每帧重下令让寻路来不及出结果；目标在直路上（卡车、路点）不受影响。若以后在别的有引用 / 要绕远路的目标上又见到"单位原地不动"，把那一族也加进 G16。
