# A4 地图为什么"简陋、一眼看完"：和原版对比的诊断

用户 2026-11-08："感觉很简陋，一眼就能看完整个地图……也不是塞更多密集的建筑就能改善的……缺少某个地图设计的 skill"。后来补充说最缺的是"地图的设计感"。
这份只做诊断（第 1 步），不改地图，按 skill 的四层来写：地方的故事、空间结构、摆放、能量化的检查。第 2 步把它做成地图设计 skill，等用户看完再做。

## 怎么比的

- **我们的**：A4 返工图 `experimental/cnv/maps/sapporo.py`，构建好的 `CampA4`（2026-11-08 15:59）。
- **原版**：红警 3 和起义时刻全部 40 张战役图用同一把尺子量；重点看场景最像的三张日本城市图：东京港（盟 7）、横滨（帝 7）、大阪（起义盟 2）。
- **尺子**：[look_measure.py](../design/teardowns/data/look_measure.py)。"中位"是原版的中位数，"N 张比它多"是实数。物体类读出 39 张（拉什莫尔山读图出错），地形 40 张。原始读数在 `work/mapdiag/*.log`（work 不进 git）。
- **对比图**（已缩小）：`work/mapdiag/map-diagnosis-a4.jpg`。左上是 A4 开局镜头，右上是 A4 的 1 号广场，中间是 A4 和东京港的俯视图，下面是大阪的俯视图和东京港局部放大。截图原件在 `work/testbench/runs/CampA4_mcp_1108_160243/`。
- **第二意见**：Gemini 看同一批图独立写了一份（没给它我的结论），见文末。

**一句话结论**：差的不是东西多少，是"像不像一个真实的地方"和"怎么摆"。我们的民用建筑比 39 张原版图里的 34 张都多。缺的是：城市该有的东西（街道设施、车、画出来的路面）；房间和遮挡（整张图正对镜头、一条直路、房子只有一排）；有理由的摆放（房子当墙、等距成排、没有小场面）。

## 第 1 层：地方的故事——像不像一个真实的地方

### 1.1 城市的"标配"没摆
- **原版**：东京港、大阪的人造物各用 116、112 种模板，排前面的是交通信号灯、路牌、长椅、各式路灯、护岸墙、卡车、小汽车、轮胎印、路锥、甲板设备。整个城市的街道设施都摆齐了，一看就是"港口城市的街"。车辆原版中位每平方公里 0.65 辆，40 张里 31 张有车，东京港 6.5 辆。
- **我们**：人造物一共 18 种：宫墙 146 段，4 种房子，再加木箱、油桶、几盏灯笼、4 面旗、鱼市摊、2 台吊车、宝塔、鸟居。**没有信号灯、路牌、长椅、车辆，运河和港口也没有护岸墙。**
- **证据**：look_measure 的 manmade_templates、vehicle_per_km2；各图最多的人造物模板清单用 `work/mapdiag/top.py` 列。

### 1.2 地面没"画"：路面贴花、地表贴图
- **原版**：路面贴花（人行道、路沿、斑马线、停车格、砖面）中位每平方公里 145 个，40 张里最少的也有 4.3 个，东京港 351 个。地表贴图中位 21 种，用得最多的一种只占 24%，28% 的格子有两种贴图之间的过渡。对比图右下角东京港放大，街区轮廓就是贴花拼出来的。
- **我们**：贴花 **0**，原版没有一张是 0。贴图 **5 种**（37 张比它多），最多的一种占 **47%**（只有 3 张比它高），过渡格 13%（37 张比它多）。路是一条土色带子，路外是一片同色雪地（对比图上排）。
- 环境音（海浪、街声）原版中位每平方公里 4.6 个，我们 0。

### 1.3 这个地方"必然有的东西"少
- **原版**：区域的身份靠它本来的东西说清楚：港口有吊车、护岸墙、甲板设备，城里有信号灯和长椅。战争痕迹（残骸、弹坑、路障）原版反而很少用，40 张里 21 张一件都没有。打仗的感觉来自敌人基地和部队，不靠废墟。
- **我们**：主题是雪祭会场，三个广场里却只有几座冰雕，没有摊位、灯笼串、围观的栏杆（对比图右上）。雪祭"必然有的东西"最少，恰恰在雪祭会场里。
- 所以第 2 步**不需要**撒废墟，要补的是"这个地方本来就有的东西"。

## 第 2 层：空间结构——房间、遮挡、先后揭示

### 2.1 整张图正对着镜头（影响最大）
- **原版**：城市整体斜 45° 摆。人造物中位 61% 斜 45°、12% 横平竖直；东京港、大阪、横滨斜着的分别占 79%、83%、89%。地形边（悬崖、海岸）中位 37% 斜、20% 横竖，40 张里 35 张斜的比横竖的多。默认镜头朝北，原版这三张的地图设置里没有改镜头角度，脚本只在过场里转镜头，所以玩家平时看到的原版城市是斜的。
- **我们**：人造物 **54%** 横平竖直（38 张里只有 1 张比它高），斜的 **2%**（比 38 张都低）。地形边 51% 横竖、7% 斜。
- **为什么要紧**（推断，第 2 步进游戏验证）：斜着摆，街道朝屏幕深处延伸，房子露出两个面，前排挡住后排，一屏被切成几块，看不全，就想往里看。正对着摆，大道横穿屏幕，房子正面朝镜头像舞台布景，往左右拖还是同一条街。Gemini 独立看图也把这一条排第一。

### 2.2 一条直路，开局就看到两头
- **原版**：40 张里 36 张开场有镜头领着看；目标"先看见、后够得着"（[layout.md](../design/teardowns/layout.md) 第三节）。
- **我们**：第 1 段主路是一条 3300 长的直线（`sapporo.ROAD_Y`，x 300～3600 没有拐弯），`missions/a4.py` 里没有镜头动作。主路旁有高地的比例 3%，原版中位 16%（`cnv_preview a4` 的 TERRAIN 行）。路不拐弯，前面就没有"拐过去才看得到"的东西。旧 A4（节日图）量过，已知区域从 11% 到最后也只有 14%，返工图没重量。

### 2.3 没有"房间"：一排房子后面是一大片空地
- **原版**：把可走的地面切成 250×250 的格子，原版中位只有 **8%** 的格子什么都没有，东京港 5%、大阪 11%。街区有进深，临街的铺面后面还有院子、后巷、矮房。
- **我们**：**28%** 的格子是空的（34 张比它少）。街两边各只有一排房子，房子后面就是空雪地（对比图上排两张的上沿和两侧，Gemini 也指出了）。三个广场都是方形宫墙院子，门宽都是 120，九成是空地。看一个就等于三个都看过了。

### 2.4 第 1 段没有地标
- **原版**：每块区域都有一个认得出的东西，而且常常就是目标本身，比如斯大林格勒的母亲像、敖德萨顺路能拆的地标、伊贺的道场（[stalingrad.md](../design/teardowns/stalingrad.md)、[odessa.md](../design/teardowns/odessa.md)）。大阪三块台地的形状、大小都不一样（对比图左下）。
- **我们**：4 个手摆的地标（宝塔、鸟居、两台吊车，`sapporo.LANDMARKS`）全在第 1 段边界外（走廊 x 300～3200、y 1700～3300）。**第 1 段能走到的地方一个地标都没有。**

### 2.5 地形轮廓：方块加随机抖动
- **原版**：人工的河岸、码头、台地是 45° 的直线段，带有意做的缺口和台阶；弯的只有自然地貌（对比图里的大阪、横滨）。
- **我们**：台地和街区先画成矩形，再用 `wobble` 把所有边都抖一遍，人工岸和自然岸抖得一样，所以既不像城市也不像自然。

## 第 3 层：摆放——有变化、有原因、有小场面

### 3.1 房子被当成墙：肩并肩、等距、同一个朝向
- **原版**：民用建筑和最近邻居的距离中位 147，参差不齐，只有 22% 的房子和邻居间距一模一样。
- **我们**：最近邻距离中位 **49**（31 张里只有 2 张更挤），**73%** 的房子间距一模一样（只有 1 张比它高）。原因：P36 / K7 用 `platmap.house_row` 一栋挨一栋排房子来封街区，玩法要一道墙，摆出来就是一长排同样的段。`HOUSE_MIX` 6 个里有 3 个是同一个模板。

### 3.2 几乎没有小场面
- **原版**：人造小物件成堆摆，讲一个小场面。按"一个人造小物件 120 以内还有另外两种人造小物件"来数，原版中位每平方公里 41 处，东京港 128、大阪 96。道具中位每平方公里 146 个，用 68 种模板。
- **我们**：**4.6 处**（37 张里 32 张比它多）。道具每平方公里 58 个，22 种模板（34 张比它多）。现有的人造物差不多就是沿大道等距一排的灯笼和旗子（`along`），外加成片撒的树。

### 3.3 疏密节奏：一条很挤，旁边一大片空
- **原版**：几乎每个格子里都有点东西，浓淡慢慢过渡（空格子 8%，比平均密两倍以上的格子 12%）。
- **我们**：空格子 28%，很密的格子 17%（36 张比它少）。东西全挤在大道两边一窄条里，其余是大片空地。问题不是没有疏密，是只有"满"和"空"两档。

## 第 4 层：能量化的检查（同一把尺子，第 2 步进 `cnv_preview`）

| 量 | A4 | 原版中位（四分位） | 对应 |
|---|---|---|---|
| 人造物斜 45° 的比例 / 横竖的比例 | 2% / 54% | 61%（38～73%）/ 12%（9～20%） | 2.1 |
| 地形边斜 / 横竖 | 7% / 51% | 37%（26～47%）/ 20%（15～23%） | 2.1、2.5 |
| 路面贴花 /km² | 0 | 145（104～243） | 1.2 |
| 地表贴图种数 / 最多一种占比 / 过渡格 | 5 / 47% / 13% | 21 / 24% / 28% | 1.2 |
| 人造物模板种数（不含树石） | 18 | 东京港 116、大阪 112 | 1.1 |
| 车辆 /km² | 0 | 0.65（0.1～3.5） | 1.1 |
| 空格子（250×250）/ 很密的格子 | 28% / 17% | 8%（4～14%）/ 12%（10～14%） | 2.3、3.3 |
| 民用建筑最近邻距离中位 / 间距一模一样的比例 | 49 / 73% | 147（74～229）/ 22%（0～53%） | 3.1 |
| 小场面 /km² | 4.6 | 41（19～69） | 3.2 |
| 道具 /km²、道具模板种数 | 58、22 | 146、68 | 3.2 |
| 第 1 段里的地标数 | 0 | 未量（地图模块要先能标"这是地标"） | 2.4 |
| 主路最长直线段、主路旁高地 | 3300、3% | 未量、16% | 2.2 |

量不了、要靠"带意图摆放"一步来做的：每个区域先写一句"这里原来是什么地方、玩家第一眼看到什么、拐过去看到什么"，再按这句话去摆地标、街道设施、小场面和遮挡。

## 附：从"效率型玩家"的角度（简短）

用户自己玩的时候关注"任务目标怎么完成、敌人从哪来"。这一节没有重新量，用的是已有的数据：
- **原版**：第一块区域里敌人中位来自 2 个方位；水和悬崖把路线收紧，40 张里 10 张根本没有陆路；备选路线要么被事件逼出来，要么要付代价才能打开（修桥、炸桥），要么是二选一（[layout.md](../design/teardowns/layout.md) 第 4、6 节）。敌人第一次露面，22/40 是玩家推进才出动的。
- **我们**：第 1 段主路上有 3 个隘口（原版中位 1），全图隘口 11（原版下限 11.2），主路旁高地 3%（原版中位 16%）。旧版 11 关里 8 关从起点到目标有 3 条以上陆路，敌人多半按计时出动（layout.md）。
- **推断**：大道又直又宽，路边没有高地，所以"占哪里、绕哪条路"差别不大，侦察也就没什么回报。这和"一眼看完"是同一个病根：空间没有切成房间。2.1～2.3 修好了，这一条会跟着变好。

## 量过、不是问题的
- 地面平不平：完全平的地面 A4 84%，原版中位 86%。
- 建筑数量和种类：民用建筑 A4 比大多数原版图多；房子模板 A4 11 种，原版中位 13 种。
- 高度层数、悬崖比例、矿、科技建筑、目标数：都在原版范围里（`cnv_preview a4`）。
- 战争痕迹：原版一半的图一件都没有，不是差距（1.3）。

## 局限
- 分类按模板名和 SageXML 的分类：克里姆林宫、横滨的建筑归到了玩家名下，读成 0 栋民用建筑，所以建筑那几项只算读得出的图。
- "为什么要紧"那几段是推断。数字是量出来的，观感要靠第 2 步在 A4 上做前后对比、进游戏看。
- 原版没有游戏内截图，测试台只能开我们的 mod，所以原版只有俯视图和数字。
- 遮挡试过按地面视线量，但 RTS 镜头是高视角，地面视线不代表玩家看到的，那一版作废了。

## 第二意见（Gemini）

Gemini 3.8 Flash 看了同样 7 张图，没给它我的数字和结论，原文在 `work/mapdiag/gem/brief.answer.md`。它的排序：1 朝向对着镜头；2 视线不被挡、没有先后揭示；3 房子只有一排深；4 广场空、没有小场面；5 地面没画；6 间距、朝向、模型重复。
- 和上面一致的：全部六条。
- 采纳的新点："房子只有一排深"和"广场九成是空地"，并进了 2.3。
- 没采纳的：它给的阈值（"60 米视线""每条街都要斜 30～45°"）是编的；原版也不是每张都斜（40 张里 35 张）。第 2 步的阈值用原版四分位。它猜开局截图里那道硬阴影是地形问题，没核实，更可能是云影。
