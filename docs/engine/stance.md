# 姿态：默认是哪个、怎么换、禁火对攻击命令做什么

引擎线第 50 轮（2026-11-06），ADR 0019 第二层。写法照 `script-semantics.md`：**测** = 测试台；**推断，未实测** = 只从资料推出来；**对不上** = 测试台和模型不一致。

探针 `experimental/cnv/checks/engine_stance.py`（`cnv_check engine_stance a` 到 `f`）。节日图西边空地，己方一辆守护者坦克 A，正前方 150 处一辆敌方守护者 T（T 挂 NO_ATTACK，e 除外）。任务第 1 秒（Test Go）起计数，姿态都用脚本动作 `UNIT_SET_STANCE`（第二个参数直接写整数：GUARD 0、AGGRESSIVE 1、HOLD_POSITION 2、HOLD_FIRE 3）。四个计数器从 Go 起**按帧累加**：帧数、T状态（1 × T 满血的帧 + 1000 × 不满血的帧，第一发命中的帧是准的）、T 血量、A 血量（百分比）。守护者一发 12.5%，30 帧一发。运行 `work/testbench/runs/CampStanceA_mcp_1106_025915` 到 `CampStanceF_mcp_1106_030945`。读数每 0.5 秒一行，所以第一发以后的命中只能说"不晚于第几帧"。

| 变体 | 做什么 | 结果 |
| --- | --- | --- |
| a | Go 时命令 A 打 T，第 45 帧设 HOLD_FIRE | 第 16 帧命中、第 46 帧前后再中一发（禁火前已打出），之后再也不中 |
| b | 开局先设 HOLD_FIRE，Go 时命令 A 打 T | 照打：第 16 帧起每 30 帧左右一发 |
| c | 不下命令，默认姿态 | A 自己开火，第 13 帧命中 |
| d | 开局设 HOLD_FIRE，不下命令 | T 一直满血 |
| e | A 设 HOLD_FIRE，命令 T 打 A | A 挨打，T 一直满血：不还手 |
| f | 同 a，第 90 帧设回 GUARD | 第 90 帧后接着打（第 98 帧前命中），原命令还在 |

## 1. 默认姿态（推断，未实测；c 只说明默认姿态会自动开火）

- 单位上只记"当前姿态"一个数；能选哪些姿态每次去查姿态模板（原版三套：Generic 四个都有、OnlyAggressive 只有进攻、OffensiveStructures 只有原地和禁火）。
- 出生后第一次更新时定默认值：**模板正好四项（Generic）就是 GUARD**，虽然它的第一项写的是 AGGRESSIVE；别的模板取第一项（OnlyAggressive 是 AGGRESSIVE，OffensiveStructures 是 HOLD_POSITION）。之前已经被地图属性或脚本设过的就不动。

## 2. 换姿态（推断，未实测；时机见第 3 节的测）

- 设成和当前一样的姿态什么都不做。
- **不查模板**：模板里没有的姿态也照设。没有姿态模块的对象忽略这条动作。
- 当帧生效。姿态定义上挂的属性修饰（原版没用）先撤旧的、再加新的。
- 载具设姿态会传给里面的乘员（没测）。

## 3. 禁火（HOLD_FIRE）（测）

- **进禁火会停住正在执行的攻击命令，但不取消它**：a 停火，f 设回 GUARD 后同一个命令接着打，不用重新下令。
- **禁火状态下新下的攻击命令照打**（b）：禁火只挡"自己找目标"，不挡命令。
- 禁火不自动开火（d），被打也不还手（e）。
- 默认姿态（GUARD）不下命令也会自己打射程内的敌人（c）。

## 4. 没进模型的部分

- 闲时自动找目标（c）、还手、HOLD_POSITION 不追、GUARD 和 AGGRESSIVE 的区别都是 AI 层的事，模型现在没有 AI 层。读程序只读到"闲时自动找目标只在 GUARD / AGGRESSIVE 下"、"HOLD_POSITION 和禁火不追"，GUARD 与 AGGRESSIVE 的距离数值没读到。

## 对不上

- c：测试台上默认姿态的 A 第 13 帧自己开火，模型里不下命令就不开火（自动索敌没建模，写成 strict xfail）。
