# 武器：开火时刻、弹道、伤害（第三层武器层）

引擎线第 24～30 轮（2026-11-05），ADR 0019 第三层。写法照 `script-semantics.md`：**测** = 测试台；**推断，未实测** = 只从资料推出来。

探针：`experimental/cnv/checks/engine_fire.py`（`timers`、`timers2`、`allI`、`allI0P`、`allI0F`、`allI00`、`shift`、`late` 八个检查跑过）和 `engine_shot.py`（`way`、`splash` 第 30 轮跑，`shells` 第 32 轮，`armor`、`flank`、`vet` 第 33 轮），读数都在各自的文档串里。

## 0. 结论：给关卡线和单位线抄的

| 想要的 | 写法 / 结论 | 状态 |
| --- | --- | --- |
| 脚本下令攻击那一帧算不算 | **不算**：单位下一帧才开始执行，弹夹装好、没有预瞄的武器下令后第 1 帧打到 | 测 + 读程序（第 31 轮） |
| 脚本下令攻击后多久打出第一发 | **单位出生（武器激活）时弹夹是空的，先装一整夹**（`ClipReloadTime`，在最小～最大之间随机取整帧），装好之前不开火。所以首发 = max(下令, 出生 + 装填) + 预瞄。V4 装填 4.5～5.5 秒、3 秒时下令：**下令后 23～38 帧 + 预瞄**。同一个单位每次一样（游戏的随机数是确定的），换一个单位就落在区间的别处 | 规则读程序（第 26 轮），区间和 16 格读数对上（测）；武器模板写 `InstantLoadClipOnActivate="true"` 就出生即满弹（推断，未实测） |
| `PreAttackDelay`（预瞄）算在哪 | 算在**发射前**：0.5 秒的预瞄平均让首发晚约 9 帧（0.5 秒 = 7.5 帧，向上取 8） | 测 |
| `FiringDuration`（开火持续）算在哪 | **不在发射前**：1 秒的开火持续去掉后首发不提前（16 格平均差 −2 帧，在单位间抖动之内）。它拖的是下一发：V4 原版约 6.5 秒一发，去掉持续后约 5 秒一发 | 测 |
| 卡"下令后 N 秒内必须打到"的题 | **刚出生的单位**（开局放的、脚本刷的、刚造出来的）首发要等一整夹的装填，且有装填区间那么宽的随机（V4 约 1 秒）。要精确时机就让单位出生后先等够最长装填时间再下令：之后首发 = 下令后第 1 帧 + 预瞄，每个单位都一样 | 测（`late` 计数器读数：没预瞄 2、有预瞄 10，读数比落地帧多 1） |
| 瞬发武器（没有弹体）的 `WeaponSpeed` | **不起作用**：开火当帧结算。`WeaponSpeed` 60 和 999999 同一帧命中 | 测 |
| 激光（`ActivateLaserNugget`） | **只画光束**，不拖时间也不出伤害；伤害靠同一个武器里的 `DamageNugget` | 测 |
| 坦克的直射炮弹飞多久 | **比瞬发晚 floor(中心距 ÷ `MuzzleVelocity`) 帧**（`MuzzleVelocity` 是每帧走的距离，不用换算）：锤子炮弹（50）打 250 / 350 / 450 / 550 远晚 5 / 7 / 9 / 11 帧；半径 0 的弹头也照样打中目标 | 测（第 32 轮四档距离）；"最后一步撞进目标当帧就炸"是推断 |
| 溅射伤害随距离衰减 | 瞄准的目标挨整份；旁边的从 `MinRadius` 处的 `Damage` 线性降到 `Radius` 处的 `DamageTaperOff`（是伤害量，不是比例），距离要减掉挨打单位的碰撞圆；**算不算在范围内却按单位真实的形状**（默认 `EXTENTS_3D`：爆炸球碰到单位的盒子/圆柱才算，盒子按单位朝向摆），所以长条单位侧面挨溅射的范围比碰撞圆算的小 | 测（锤子 0/40/80/120 远掉 20/17/9/0%）+ 读程序（第 33 轮） |
| 伤害类型 × 护甲 | 伤害 × 护甲模板里该类型的百分比（没写的用 `Default`，默认 100%），不截断；整表见第 4 节 | 测（锤子：GUN 50%、AUTO_CANNON 25%、IMPACT 75%、RADIATION 5%）+ 读程序 |
| 打侧面、打背面 | 看**攻击者所在方向**和挨打单位朝向的夹角：超过 45° 乘 `SideDamageScalar`，超过 135° 乘 `RearDamageScalar`（坦克 105 / 110） | 测（0°/40°/90°/180° 掉 40/40/42/44%）+ 读程序 |
| 老兵加成 | 按经验到级：老兵 伤害 ×1.25，精英 血 ×1.25，英雄 射程、视野 ×1.25、射速 ×1.2；**升上去后前几级的加成保留**（精英也有老兵的伤害加成） | 测（V4 0/老兵/精英/英雄 首发 5/6.25/6.25/6.25%） |
| 属性修正（`AttributeModifier`）怎么叠 | 同一种修正：大于等于 100% 的**相加**（150% 加 200% = 250%），小于 100% 的**相乘**；`ARMOR` 是挨打的倍数（25% = 只挨四分之一，150% = 多挨一半） | 读程序（第 33 轮），原版数据的用法相符；没上测试台 |
| 散布 `ScatterRadius` / `ScatterRadiusVsType` 怎么取 | 打单位时：**第一条对得上的 `ScatterRadiusVsType` 直接替换 `ScatterRadius`**（不相加；那条写 0 就是不散）；落点 = 目标位置 + 0～R 之间均匀取的距离（不是圆盘均匀，近处更密），**角度只在朝射手的那半圈**；散了的炮弹不追目标、目标也不再算直击，伤害只靠落点：半径 0 的弹头要落进单位的盒子里（炮弹撞上）才打中，打桥例外（仍直击） | 读程序（第 34/35 轮）+ 测（锤子炮弹 R 0/30/60/120 命中 100/66/36/6%，模型期望 100/62/31/16%）；“撞上”是推断 |
| `HitPercentage` | 没有散布半径时，小于 100% 就每发掷骰，没中就按“散了”处理（落在目标位置、不算直击）：瞬发武器半径 0 就是打空 | 读程序；没上测试台 |
| `missile.md` 里"有的道固定晚 8 帧" | 不是道的问题，是上面那个单位间抖动：同一条道换个单位，先后顺序就变了（第 1 节表） | 测 |

## 1. 开火时刻（第 24 轮建、第 25 轮跑）

场景：平地探针图（`maps/probe_range.py`）四条道 base、high、removed、switch，每条一个射手（朝北）+ 正北远处一个 10000 血的锤子坦克靶子（`NO_ATTACK`）。射手是原版 V4 的四个改版：火箭换成**一发当帧结算的伤害**（`DamageNugget` 500、半径 0、`WeaponSpeed` 999999，没有飞行）、**去掉散布**，只改两个时间：

| 改版 | 预瞄 | 开火持续 |
| --- | --- | --- |
| 原时 `CNV_FireI` | 0.5 秒 | 1.0 秒 |
| 无预瞄 `CNV_FireI0P` | 0 | 1.0 秒 |
| 无持续 `CNV_FireI0F` | 0.5 秒 | 0 |
| 都无 `CNV_FireI00` | 0 | 0 |

开局四个改版在每条道上各放一个，检查开局删掉不用的。射手和靶子开局 `NO_ATTACK`，3 秒时放开射手并 `NAMED_ATTACK_NAMED`。计数 = 下令到首中的帧数 + 每掉 1% 血加 1000（一发 5%）。

**下令到首中（帧）**，每格是一次测试台读数；`timers`、`timers2` 把改版在道之间对调，`all*` 四条道放同一个改版：

| 改版 \ 道 | base | high | removed | switch | 平均 |
| --- | --- | --- | --- | --- | --- |
| 原时 | 35 | 46 | 38 | 36 | 38.8 |
| 无预瞄 | 33 | 23 | 30 | 31 | 29.3 |
| 无持续 | 45 | 38 | 40 | 41 | 41.0 |
| 都无 | 32 | 23 | 35 | 38 | 32.0 |

- **确定的**：`timers` 原样重跑一次，四个读数一模一样（35 / 23 / 40 / 38）；交叉的 `timers`、`timers2` 八个读数和 `all*` 里对应的格全部相同。同一格不受别的道放什么的影响。
- **没有预瞄的 8 格落在 23～38**，有预瞄的 8 格落在 35～46（第 25 轮的读法："约 23 帧 + 0～15 帧单位间抖动 + 预瞄"）。
- **第 26 轮读程序找到的规则**：武器状态机的初始状态，在模板没开 `InstantLoadClipOnActivate`（默认关）、弹夹大于 0 时，在武器造出来那一帧就开始装一整夹，时长 = 在 ceil(15×最小) 和 ceil(15×最大) 之间随机取整帧（V4：68～83 帧）；预瞄只能在装填结束、进入"就绪"之后开始。单位开局（第 0 帧）出生、第 3 秒（第 45 帧）下令：没有预瞄时 68－45 = 23 到 83－45 = 38，有预瞄再加 8 帧 = 31～46。16 格全在区间内，两端 23 和 38 各出现两次、46 出现一次。"单位间抖动"就是每个单位出生时抽到的装填时长，不是周期也不是相位。
- **第 30 轮两个对照**：`shift`（同样四个单位、4 秒下令）读数 20 / 8 / 25 / 23，每格正好比 `timers` 少 15，规则证实：装填从单位出生算起，跟下令无关。`late`（6 秒下令，弹夹早装好）读数 10 / 2 / 10 / 2：没预瞄的是常数 2 帧，有预瞄的再加 8。
- 私有模型照此改了，区间宽度、预瞄差、`shift` 的平移都对。**读数要减 1 才是伤害落地的帧**：游戏每帧先跑脚本（计数器在这里加）、再更新物体，本帧扣的血下一帧脚本才看见。下令那头第 31 轮对上了：脚本下令后单位要到**下一帧**才开火，所以弹夹装好的单位下令后第 1 帧落地（读数 2），模型改了。装填那头第 32 轮也对上了（23～38）：开局摆的单位在加载时、第 0 帧建好，弹夹从第 0 帧起装；第一次跑脚本和第一次更新物体都在第 1 帧（游戏每帧先把帧号加 1 再跑脚本）。模型原来第一次跑脚本记作第 0 帧，所以晚 1，改了。游戏在装好那一帧当场开火、不隔帧。
- 后面几发：都无约 5 秒一发（装弹 4.5～5.5 秒），原时约 6.5 秒一发。

## 2. 弹道和溅射（第 29 轮建、第 30 轮跑）

场景：同一张平地探针图，射手都是上面"都无"那个 V4 改版（没有预瞄和开火持续，也没有散布），6 秒时下令（弹夹已装好）。只换弹头和 `WeaponSpeed`。

**`way`**：四条道，靶子在正北远处（约 450），读数是下令到首中的帧数，每发都掉 5%：

| 道 | 武器 | 下令到首中 | 模型（第 32 轮） |
| --- | --- | --- | --- |
| base | 瞬发，`WeaponSpeed` 999999 | 2 | 2 |
| high | 瞬发，`WeaponSpeed` 60 | 2 | 2 |
| removed | 原版锤子炮弹（直射，`MuzzleVelocity` 50），弹头是一个半径 0、伤害 500 的 `DamageNugget` | 11 | 11 |
| switch | 激光（原版 LockDown 用的激光 nugget）加一个伤害 500 的 `DamageNugget` | 2 | 2 |

- 瞬发武器不看 `WeaponSpeed`（《将军》里要等 距离 ÷ 速度，60 的话约 113 帧）；激光不拖时间。
- 炮弹比瞬发晚 9 帧 = floor(450 ÷ 50)，见下面 `shells`。
- 半径 0 的炮弹弹头照样打中目标（爆炸点放到目标身上）。
- 常数 2 就是第 1 节"下令后下一帧开火"。

**`shells`**（第 32 轮）：同一个打锤子炮弹的 V4，射程改成 800，四辆分别打正北 250 / 350 / 450 / 550 处的锤子。读数 **7 / 9 / 11 / 13**（改模型前模型是 9 / 11 / 13 / 15）：

- 每远 100 正好晚 2 帧：飞行时间只看中心距 ÷ `MuzzleVelocity`，没有别的随距离变的项，"发射点在炮口、实际距离短 100"这个解释排除了。
- 常数：落地帧 = 发射帧 + floor(距离 ÷ 50)。程序里发射当场就从"待命"转"直飞"（不单占一帧）；剩下那 1 帧按碰撞解释：第 n 步正好落到目标中心、进了它的碰撞体，当帧就炸，不等下一帧判"到了"。碰撞那条路程序没读，是推断。打地面一个点（没有目标物体）时按程序读的走：再晚 1 帧。
- 模型照此改了，`way` 和 `shells` 都对上。

**`splash`**：一发伤害 2000（锤子 10000 血的 20%）、半径 100、`DamageTaperOff` 20；瞄准一辆锤子，另外几辆摆在它东边 0 / 40 / 80 / 120 处。第一发各掉 **20 / 17 / 9 / 0%**（模型 20 / 17 / 9 / 2）。

- 衰减算距离时要减掉挨打单位的碰撞圆：40 和 80 正好对上；如果不减，40 处只会掉 12%。
- 但 120 处那辆（中心在半径外，减掉碰撞圆以后在半径内）一点没掉。第 33 轮读程序找到原因：判断"在不在范围内"按的是单位真实的形状，不是碰撞圆。锤子是长 20、宽 14 的盒子，敌方单位默认朝南，所以东边只伸出 14，最近的边离炸点 106，超过半径 100。模型照此改了，对上。
- 第 4 发开始，0 处那辆不再掉血、另外几辆每发只掉 9%，原因没读，可能是几辆锤子被挤开了；只用了第一发的读数。

## 3. 还不知道的

- 炮弹是不是真靠碰撞提前 1 帧（会不会半路撞上别的单位）。
- 追踪修正 10 的 V4 导弹追跳开的锤子（第 44 轮重看）：原来的说法是"装填区间最低那一头偏 56、打不中"，但测试台只跑了一次抽签，那一局第 116 帧打中。按这个时刻对上抽签后，模型也在第 116 帧打中，修 2、修 5 照样落空，修 20 差 1 帧。
  - **还剩的**：模型里这发落在锤子旁边，弹头按距离衰减后只掉 4%，测试台掉满 5%（模型里 strict xfail）。对关卡推演的影响：追得上的导弹打跳开的目标时，伤害可能少算两成；打不打得中、什么时候打中都不受影响。
  - 读程序找到两条模型里没有的规则，是剩下的两个假设：一是贝塞尔弹体爆炸时有一条"直接命中目标"的分支（目标还活着，加上武器模板里一个布尔字段和一个关系判断都过了，就让弹头对准目标结算，像是不看距离）；二是飞行途中碰到物体的几何体，就退回入口点当场引爆。试过只加第二条：修 10 那发在模型里根本没擦到锤子，解决不了；对静止靶的命中还会早 2 帧，测试台没有逐帧读数支持这个改动，所以没留在模型里。
  - 继续查要做三件事：一是读"直接命中"分支用的那个关系判断，以及那个布尔字段对应 XML 里哪个字段；二是读弹头"对指定目标结算"那一步看不看距离；三是加一个测试台探针，让同一发导弹分别落在锤子身上和旁边 20、40 处，看伤害是满额还是按距离衰减。
- 弹夹打空后的装填、`InstantLoadClipOnActivate`、换武器（升级、切换武器组）时是不是也重新激活装填，都没测。
- 射手要转身、目标在射程外要走近时多花多少。
- `MinRadius` 不为 0 时的衰减、`DelayTimeSeconds` 延迟伤害、炮弹的 `Acceleration`，都只读了程序，没测。
- 散布：锤子炮弹 R 120 测试台命中 6%，模型期望 16%（3 个标准差之内；测试台随机数固定，两次读数完全相同，所以复跑没用）。`CanBeDodged` 的闪避掷骰（挨打单位给的值）没读也没建模；打地面时 `ScatterIndependently` 每个弹头重取、`ScatterLength` 的两种排开方式只读了程序。
- 装填 0.5 秒、弹夹 1 发（第 44 轮测清）：**稳定后 8 帧一发**（0.5 秒 = 7.5 帧，向上取 8），模型对上。测法：`engine_scatter` 新加 `cyc` / `span` 两个检查，让地图脚本数"第 a 发命中到第 b 发命中"之间的帧数，不看观察窗口的秒数。第 5～41 发读数 48 / 80 / 160，和模型一模一样。第 35 轮说的"24 秒 50 发、约 7 帧一发"是读错了：观察窗口的秒是按墙钟乘倍速估的，它的 30 秒实际比任务的 30 秒多走了约 3 秒。
  - **还剩的**：开打后头 4 个间隔每个只有 7 帧（第 1～5 发 28 帧，模型 32 帧），之后都是 8 帧（模型里 strict xfail）。对关卡推演的影响：快速连发的武器前 5 发总共早到 4 帧（约 0.27 秒），总伤害和稳定射速不变。没查清的假设有两个：一是射手刚开打时还在转身或抬发射架，头几发飞行时间一发比一发短；二是头几次装填提前一帧开始算。继续查要做两件事：一是在 `span` 里把"下令到第 1 发命中"和单个间隔分开数；二是换一个不用转身、靶子正对着的布置复测，看这 4 帧还在不在。
- 护甲那几条没测的：一个单位有几套护甲（升级、被冰冻）时怎么选；`FlankedPenalty`、`FlankingBonus` 只对 HORDE 类单位起作用，没细读；`ARMOR` 修正的叠法没上测试台；击杀给的经验没建模。

## 4. 护甲、侧击、老兵（第 33 轮）

探针 `engine_shot` 的 `armor`、`flank`、`vet` 三个检查，读数在文档串里。挨打的都是 10000 血的锤子，计数器记掉了几个百分点（刚开始掉的那一格也算，所以 6.25% 读作 7）。

- **护甲表**：原版 156 个护甲模板 × 39 种伤害类型，`work/re/armor_table.csv`（不进公开仓库）。原版武器最常用的伤害类型是 EXPLOSIVE（54 个）、ROCKET（20）、AUTO_CANNON（18）、CANNON（14）。征召兵挨 TESLA 是 1000%。
- **一次伤害怎么算**（读程序）：射手那边，衰减后的伤害 × 第一个对得上的 `DamageScalarDetails` × 射手的 `DAMAGE_MULT`；挨打那边 × `DamageScalar` × 侧面/背面系数 × 该伤害类型的百分比 × 挨打单位的 `ARMOR` 修正。`HEALING` 什么都不乘；`UNRESISTABLE` 只乘 `DamageScalar` 和侧面/背面，不乘百分比和 `ARMOR`；`FORCE` 不乘 `ARMOR`。
- **侧击**：正面 40%、偏 40° 还是 40%、侧面 42%、背面 44%。看的是开火那一刻攻击者站的位置。模拟器（第 186 轮，`Sim.flank_of`）：持续火力、逐发命中、直线炮弹（发射那一刻算）都乘；`UNRESISTABLE` 也乘（`engine_inform_ai` 侧面矿车 68%）；`StripMaxHealthPercent` 跟着乘是推断；DOT、打驻军乘客不乘（没有来路，推断）。测试 `tests/test_simbench_c.py` 按 `engine_shot flank` 对拍。
- **走动中的车体朝向**（第 187 轮，`engine_hull`）：朝南的锤子被派往北 / 东 / 身后 120，开火时分别吃背面 / 侧面 / 背面（40 / 44 / 42 / 44，第一个是原地不动的对照）；派往北、命令后 0.15 秒挨打就已经是背面。车体朝走的方向，短距离往后走也不倒车，转身快到台上量不出来。模拟器（`Sim.move`）：这一步动了的单位立刻朝这一步的方向（瞬间转身是推断）。测试 `tests/test_simbench_c.py::test_hull_...` 按 `turn` / `rate` 对拍。
- **死亡武器也吃侧击**（`engine_crash_face`）：坠机残骸砸在锤子身上，朝东、北、西、南四辆掉到 70 / 71 / 71 / 70%（背面 / 侧面 / 侧面 / 背面），原地落下的残骸算正面（72%）。残骸停在离坦克中心差一点点的位置，偏差的方向随坐标变（推断是浮点误差），所以"正好砸在中心"时算哪一面没法按来路预测；模拟器按来路算，记了 strict xfail。
- **老兵**：原版 V4 给 0 / 3600 / 7200 / 10800 经验（1～4 级），首发 5 / 7 / 7 / 7。老兵的 ×1.25 伤害到精英、英雄都还在。英雄第二发来得更早（射速 120%）。
- **坑**：复制出来的单位（换了 id）就算自己带一套 `ExperienceLevelTemplate`，给经验也不升级（四级都是 20%）。要测老兵就用原版单位。
