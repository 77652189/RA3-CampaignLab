# 反编译试探：红警3游戏程序能不能回答战役用到的引擎行为

日期：2026-11-04。引擎线第 1 轮。用户 2026-11-04："那我们就只做战役用得到的部分，反编译后得到文档，只用来做mod，研究学习里面的内容，不公开。"

规矩：反编译产物（Ghidra 工程、伪代码、脚本）只在 `work/re/`，不进 git、不外传。本文只用自己的话写行为，引用时只写函数地址（1.13 版）。

## 1. 对象和工具

- 测试台实际运行的是 `RA3_1.13.game`（`harness.py` 启动参数 `-runver 1.13`），不是 1.12。两份都复制到了 `work/re/`，只分析了 1.13 的副本。两版都没加壳；1.13 编译于 2025-02，代码段比 1.12 大约 0.4%，资源段大很多（多了图标之类），脚本系统的结构应该相同，但地址不通用，1.12 没逐个核对。
- 工具：Ghidra 12.2 + Temurin JDK 25，装在 `../tools/`。坑：Ghidra 12.2 要求 JDK 25（装 21 不行）；JDK 目录名里带 "+" 时启动脚本认不出来；默认的用户配置目录在 `AppData\Roaming` 下时，OSGi 报 "data file must be inside the data dir"，所以在 `support/launch.properties` 里加了 `-Dapplication.settingsdir=` 指到 `../tools/ghidra_settings`。全程序自动分析约 3 分钟。
- 用法：`work/re/scripts/run.sh f:<地址> x:<地址> ...`（`Dump.java`：f 导出伪代码、x 列引用、c 列调用者、m 先建函数再导出、j 列大跳转表），输出在 `work/re/out/`。`work/re/scripts/vt.py` 找重写了某个虚函数槽位的子类。

## 2. 脚本系统的入口（读代码得出）

- 动作名字表在 `0x5847e0` 里逐条登记，条件名字表在 `0x5936f0`，和《将军》的 `ScriptEngine::init` 一样的写法。登记顺序号就是 `script_catalog.json` 的 `ctype`（例如 `MOVE_TEAM_TO`=13、`SHOW_MILITARY_CAPTION`=116、`NAMED_FIRE_SPECIAL_POWER_AT_WAYPOINT`=137、`ATTACK_MOVE_TEAM_TO`=413）。
- 动作分派在 `0x5cd560`：先看动作自己的"启用"字节，关着就整条跳过；然后按编号查 573 项跳转表（`0x5d7a8c`），每一项取参数再调对应的处理函数。条件分派的跳转表在 `0x5c6a60`（151 项）。所以以后查任何一个动作，只要按 `ctype` 查这张表就能直接找到处理函数。

## 3. 三个问题

**② 整队命令（`MOVE_TEAM_TO` 处理函数 `0x5a46a0`，`ATTACK_MOVE_TEAM_TO` 走 `0x5a4750`）—— 代码 + 测试台都有，对得上。**
- 代码：按名字找队（`0x59e750`）→ 新建一个 AI 组 → 把这个队**此刻**的成员装进组（`0x865d70`）→ 整个组移动到路点。命令发给的是这个临时组，不是队本身。和《将军》的 `doMoveToWaypoint` 一模一样。
- 推论：下令之后才进队的单位不会跟着走，下一次命令才会；只要下令那一刻单位在队里，就都会动。
- 测试台 2026-11-04（`cnv_check team once`，本轮重跑）：放在图上的 3 辆车全部到终点；第 8 秒才造进队的车（队里人数读到 4）始终没到。和关卡线同日的探针结果一致。所以"整队命令一辆都不动"的旧现象不是引擎语义造成的；要再出现，先查单位当时是不是真在这个队里。
- 还没读：《将军》里按名字找队时，"单例队伍未激活就返回空"会让命令整个落空；红警3的 `0x59e750` 是否保留这一条，下轮读一下就能确认。

**③ 脚本放技能（`NAMED_FIRE_SPECIAL_POWER_AT_WAYPOINT` 处理函数 `0x5ba2e0`）—— 处理函数读过；绕过放置规则的现象此前测试台已见过（`checks/a4.py` 的旧 `ice_at`，见 `docs/reviews/architecture-2026-11-03.md` K3 一行）；技能模块内部没读。**
- 代码：找单位、找技能模板、取单位身上对应的技能模块、找路点，然后**直接调用模块的"在某地施放"**（虚函数槽 0x34），带标志 8（对应《将军》的"脚本下令"）。中间没有任何位置是否合法的判断，和《将军》相同。
- 推论：放置规则（能不能放在这里）只在玩家点击那条路上检查，脚本这条路根本不走那里。所以要检查放置规则，只能让检查走玩家点击（这和 ADR 0016 K3 的做法一致）。
- 没核对：模块本身收到标志 8 时会不会另做检查；玩家点击那条路上的检查函数在哪。

**① 字幕（`SHOW_MILITARY_CAPTION` 处理函数 `0x5a5eb0` → `0x5a1f80`）—— 只读到一半，没有结论。**
- 代码：脚本动作不直接画字幕，而是把（字幕键, 秒数）广播给一张"脚本界面监听者"名单（约 40 个界面类动作共用这张名单）。15 个界面类继承了这个监听者基类（构造函数 `0x5a2380`），只有一个类重写了字幕这一格（`0xa5e6e0`）：它把秒数换成毫秒，按字幕键取文本（`DIALOGEVENT:` 开头的键另有处理），再交给自己内部的一个显示对象。累积和"约 5.4 秒后整栏清空"的逻辑在那个显示对象里，本轮没追到。
- 数据线索：游戏数据里有 `UISubtitleDisplay`（零售值 `HoldTime=20s`、`LineCount=8`）和 `UIMilitaryCaptionDisplay`（`Delay` 默认 750ms），见 SDK `SageXML/UI/SettingsCommon.xml`。8 行的日志框和"累积"相符，但 20 秒和实测的 5.4 秒对不上，可能是另一处常量或界面动画（Apt）里定的。

## 4. 闸口

要求：三个问题里至少两个能从代码得出结论、并和测试台对得上。
- ② 过：代码 + 本轮测试台。
- ③ 半过：处理函数结论明确，和以前测试台见过的现象一致；但模块内部没读，也没有本轮专门的测试台核对。
- ① 没过。

**判断：勉强过闸。** 找函数这一步很顺（名字表→跳转表→处理函数，每个动作几次调用就到），难的是界面这一侧：字幕走虚函数和广播，静态追要一层层找子类。花费：本会话约 18 万上下文，其中装工具踩坑约占三分之一。

## 5. 如果铺开

- 每个动作或条件：查跳转表 + 读处理函数，一般 2～4 次调用；纯逻辑的（移动、生成、血量、计数）大概一轮能做 10～15 个。
- 先做的：第 6 节那 28 个查不到的动作里，关卡正在用的移动、生成、血量类（`ATTACK_MOVE_NAMED_UNIT_TO`、`UNIT_TELEPORT_TO_WAYPOINT`、`UNIT_GUARD_AREA`、`UNIT_SET_HEALTH`、`CREATE_NAMED_ON_TEAM_AT_WAYPOINT_WITH_ORIENTATION`），再做条件 `PLAYER_HAS_COMPARISON_UNIT_KIND_IN_TRIGGER_AREA`（"所有玩家都算"的矛盾）和 `"Mission Won"` 旗标在哪里被读取。
- 界面类（字幕、目标、计时器显示）每个要多花 1～2 轮，建议只在有具体问题时再追。
- 估计：把 `script-semantics.md` 第 6 节列的条目全部过一遍，大约 3～4 轮。
