# 出售建筑：退多少钱、什么时候给、要几帧、建筑里的兵

引擎线第 49 轮（2026-11-06），ADR 0019 第二层。写法照 `script-semantics.md`：**测** = 测试台；**推断，未实测** = 只从资料推出来；**对不上** = 测试台和模型不一致（本轮没有）。

## 1. 退多少钱（测）

- 退款 = 造价 × 50% × 当前血量比例，两步都四舍五入。满血电厂退 400（a），半血退 200（b），碉堡退 250（d）。
- **受伤的建筑退得少**，这一点和《将军》不同（那里不看血量）。
- 50% 来自全局设置 SellPercentage（SDK 默认值，原版 XML 没改）；模板上写了 RefundValue 的就用它代替"造价 × 50%"（**推断，未实测**：原版建筑都没写）。
- 按全额造价算，不看已经付了多少（**推断，未实测**：施工中本来就卖不了，见第 3 节）。

## 2. 什么时候给钱、要几帧（测）

- **开卖当帧就给钱**，不是卖完才给：e 卖到一半被打死，钱已经到账，也不会再给。
- 开卖当帧就挂上 SOLD（同时变成不能选中）。
- SellTime（建筑基类 2 秒）× 15 四舍五入 = 30 帧后删除；加上开卖那一帧，脚本一共看见它 31 帧（a）。缺电不影响这个时长（**推断，未实测**）。
- 删除不走死亡流程：没有死亡效果、不留废墟、不算击毁（**推断，未实测**：只看了模型状态和对象消失）。
- **卖的这 30 帧里建筑照样算电**，删掉那一帧才少（a 的第四行）。也能被打、被打死（e）。
- 同一座楼重复卖只算一次（f）。

## 3. 哪些卖不了（测 + 推断）

- **施工中卖不了**：脚本造出来的建筑在展开期间带"施工中"状态，卖了没反应，钱不变、之后照常展开完（c）。
- 不是建筑的（单位）、模板标了 NOT_SELLABLE 的、已经在卖的、已经死了的，都静默无效（**推断，未实测**，单位那条只在模型里测了）。
- 脚本卖的时候**不看** CANNOT_BE_SOLD 状态、展开状态、断电、被禁用，也不看是谁的建筑，对人类玩家的建筑一样生效（**推断，未实测**）。玩家点卖按钮那条路会不会查 CANNOT_BE_SOLD 没读到。
- `PLAYER_SELL_EVERYTHING` 对每座建筑走同一个入口，卖不了的跳过（**推断，未实测**）。

## 4. 建筑里的兵、工厂的队列（推断，部分测）

- 驻军建筑在**开卖当帧**被告知，兵出来，不随建筑删掉（**推断**）。d 里兵一直活着、从 Go 起都不在里面，和"开卖当帧放出来"一致；但计数器从开卖那帧才开始数，分不清兵是开卖时出来的还是根本没进去，所以这条**还没测实**。下次在 Go 之前先数一次"在里面"。
- 工厂开卖当帧取消整条队列，已付的钱退回，之后不再生产（**推断，未实测**，只在模型里测了）。

## 5. 模型

私有模型 `ra3model/objects/sell.py`：出售入口（拒绝条件、SOLD、通知各模块、退款入账）和 StructureSellUpdate（30 帧后删除）；工厂和驻军各加了"被卖"的处理。六个变体的终值和第一行之后的逐帧读数都和测试台一致。BuildingBehavior 只管平民建筑的窗户灯光（画面），不进模型。
