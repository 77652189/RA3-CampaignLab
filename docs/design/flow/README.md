# 流程剧本（第 1 层：剧情与流程）

每关一份，写的是玩家从读简报到看见胜利画面，**看见什么、听见什么、知道要做什么**。这是 [ADR 0008](../../adr/0008-levels-by-layer.md) 第 1 层的产出，工作流见 [charter.md](../charter.md)"三层"一节。

- 不写数字（兵力、血量、秒数只写大概，"约 3 分钟"），不写摆放：那是第 3 层。
- 不写地形细节：那是第 2 层（地图内容）。这里只写到"2 号广场""北营"这样的地名，第 2 层给每个地名配上地方本身。
- 剧情以大纲 [outline.md](../../story/outline.md) 为准，悬着的问题见 [story-questions.md](../story-questions.md)。人名用 [cast.md](cast.md) 的键。

## 一、文件

| 文件 | 是什么 |
|---|---|
| [cast.md](cast.md) | 角色表：谁会说新台词、谁只能说原版台词；术语以哪份表为准 |
| [mechanics.md](mechanics.md) | 剧本能承诺什么：机制和引擎事实，已确认 / 待验证 / 不能做，各带出处 |
| [flowcheck.py](flowcheck.py) | 机器检查：完整和一致（第四节） |
| [flowmap.py](flowmap.py) | 示意图对到实际地图：地方的块和点换算成位置，每段的可玩区，地图的地形、路和地块用途表给网页画底图；flowcheck 和 flowview 都用它 |
| [flowview.py](flowview.py) + `flowview.html` | **给用户看的网页**（总控 2026-10-28 加）：`python docs/design/flow/flowview.py` 生成 `work/flowview/flow.html`，三种看法：玩家视角从简报逐句放到结局；五条审核（用户 2026-10-29 的标准，一条一块）；整关一张表（每段的镜头、目标、事件、提示、卡住，谁说了多少、每分钟几句台词），flowcheck 的问题列在最上面。用户说只读 md 看不出问题，所以交给用户审的剧本都先生成这个网页。改了 yaml 的字段名或结构，`flowview.html` 里的读法要跟着改 |
| `<关号>.md`（如 `a4.md`） | 每关一份流程剧本 |

## 二、每关写什么

每份流程剧本是一个 markdown 文件：开头几行人话说明，正文是一个 `yaml` 块（和策划案一样，方便机器检查，以后也能直接生成字符串表和脚本）。

```yaml
关: A4                          # 关号
关名: 冰雕里的兵
阵营: 盟军
类型: 护送                       # 护送 / 突击 / 基地对抗 / 守 / 潜入 / 海战 / 限时 / 打自己人
位置: 中期                       # 前期（1～3 关）/ 中期（4～6）/ 后期（7～9），要和关号对得上；规模的下限见 P31
基地: 中途                       # 开局 / 中途 / 无；后期写"无"要再写一行 无基地的理由
综合: [纸鹤侦察机, 合体机甲]       # 只有后期关要：这条线前面几关给过、这一关要一起用的工具，至少两样
地点: 札幌·雪祭会场
新东西: 冰幕工兵                  # 这关解锁的单位或机关；没有写 —
用到的机制: [冰墙封门, 揭图]        # 剧本承诺玩家能做、能看到的机制，写 mechanics.md 的键
出场单位:                         # 剧本里提到、玩家会见到的单位和防御，叫法照术语表
  我: [冰幕工兵, 守护者坦克]
  敌: [帝国武士, 坦克杀手]
一句话: 护送一车克隆体穿过雪祭到港口……   # 第 1 步：身份 + 新花样 + 转折
体验目标: 冰是借来的时间……          # 第 2 步
取舍:                            # 第 2 步：三个关键取舍，玩家在哪一刻要选什么
  - 现在冻还是等一等
张力: 拮据 → 掌控 → 最后最紧        # 各段的感觉
接上一关: 玩家这时知道什么、为什么还照命令走
引出下一关: 胜利交代了什么，下一关为什么发生

# ---- 用户的五条审核标准（2026-10-29，第三节第 16～20 条）：每条对应下面一项，都必填 ----
故事:                             # 第 1 条（P32）：一关一个完整的故事
  开头: 谁想要什么，为什么是今天
  起伏:                           # 按先后，至少三处；顺 = 对玩家有利，逆 = 不利，两种都要有
    - {段: 港口生变, 向: 逆, 事: 桥头被堵，车过不去}
    - {段: 北营, 向: 顺, 事: 司令给了一座基地}
  结尾: 谁得到了什么、谁失去了什么
人物:                             # 第 1 条：这关里说三句以上台词的角色每人一条（播报除外）；只说原版台词的英雄也可以写
  - 谁: 沃斯                      # cast.md 的键
    想要: 把车送到，也想知道收货的是谁
    转折: {段: 最后一程, 事: 看见未来科技的旗，被司令一句"专心护送"顶回去}
    看得出: 玩家从哪句台词、哪个镜头看出来
开局:                             # 第 3 条（P33）：定性，不写数字
  手上: 开局玩家有什么兵、建筑、钱；什么时候给基地
  敌方: 压力多大、从哪来、能不能拆（P6）
解法:                             # 第 3 条：至少两种能通关的打法
  - {打法: 冻门放车，不硬打, 段: 会场, 提示: 开场沃斯说"那里只能冻"}
平推会怎样: 只造兵往前推会遇到什么，为什么比别的打法慢、贵或险（按用户的打法想：会换兵、会微操、先拆光压力源）
意外:                             # 第 4 条（P34）：至少一处
  - 名: 海上来的天狗
    段: 最后一程                   # 在哪一段撞上
    初见: 第一次玩的人怎么撞上它
    伏笔: {段: 北营, 事: 二周目的玩家从哪里看得出来}   # 段写简报或这一段以前的段
    准备: 有经验的玩家提前做什么
    补救: 防空援军                 # 下面保底里的一条（名），意外和保底配对
保底:                             # 第 5 条（P35）：可能坏档的地方，至少一处
  - 名: 防空援军
    段: 最后一程
    坏档: 卡死的样子（钥匙单位全死、没兵没钱还有一大段要打）
    条件: 这一段还没完成，玩家的某种兵少于若干个（只送一次）
    援军: 送什么
    从哪来: 港口                   # 示意图里的地方（名或又名）
    点: harbour                   # 有实际地图时：援军在地图的哪个地点出现
    台词:
      - 沃斯: 原文。
摆放要求:                         # 第 2、3、5 条写成关卡线照着摆的要求（第 21 条，ADR 0009）；点 = 地图的地点
  边界:                           # 可玩区每变一次写一条：哪一段、换成哪块（和示意图的可玩区一样）、什么时候切
    - {段: 港口生变, 换成: west of the canal, 何时: 过场镜头往北推到北营的那一刻}
  资源点:                         # 至少一处：矿、油井、能占的建筑；为了 = 它撑哪种解法
    - {地方: 南坡下, 点: south ramp, 段: 北营, 什么: 一座油井和一块矿, 为了: 解法"派工程师占油井"}
  伏击点:                         # 至少一处：敌人必经、玩家能先摆好的地方
    - {地方: 北坡口, 点: north mouth, 段: 最后一程, 什么: 一百二十宽的口子, 为了: 冻住口子，炮架在后面}
  援军:                           # 保底以外按进度或定时给的（交基地也写这里）；保底的位置写在保底的 点 里
    - {地方: 南高原, 点: south base, 段: 港口生变, 什么: 一辆基地车和一笔钱, 为了: 交基地}

简报:                            # 进关前，读图界面上播的那段
  - 沃斯: 原文。

段:                              # 按时间顺序，第一段通常是开场镜头
  - 名: 开场
    时长: 约 15 秒
    镜头:                        # 镜头给玩家看什么，按顺序；可以带台词
      - 看: 车队从西边图外开进来
        台词:
          - 沃斯: 原文。
  - 名: 会场
    时长: 约 3 分钟
    动词: 护送                     # 这一段玩家在做什么；有主目标的段都要写（P31 数种数）
    敌军:                         # 写了动词的段都要写（P29，第 22 条）：每种兵怎么来、玩家拿什么克制；喘息段写"无：为什么"
      - {兵: 帝国武士, 怎么来: 摆好的，冰雕里的伏兵, 克制: 冻门；维和步兵}
      - {兵: 坦克杀手, 怎么来: 摆好的，冰雕里的伏兵, 克制: 别让车停下；多功能步兵车}
    目标:                        # 这段新亮出的目标，原文
      - 种: 主                   # 主 / 奖励
        亮出: 走到后巷坡下          # 可选：不写就是这段一开始亮出
        题: 护送车队到二号广场      # 任务菜单里那一行
        说明: 原文。               # 选中目标时下面那段话
      - 种: 奖励
        题: 占领后巷的修理厂
        说明: 原文。
        回报: 打残的兵撤回来就能修好   # 奖励都要写：玩家拿到什么（钱、兵、科技、揭图、捷径；P16）
    事件:                        # 这段里会发生的事，按先后；台词、镜头、揭图、标记
      - 时机: 交还控制
        台词:
          - 沃斯: 原文。
      - 时机: 玩家还没用过冰幕工兵
        文字: 信息框挂在工兵头上的那句话   # 只给新机制和失败原因用（准则第 8 条）
    下一步靠什么:                 # 玩家靠哪几样知道要去哪、做什么
      - 目标说明点名 1 号广场
      - 小地图上 1 号广场闪
    卡住了:                       # 玩家没做对、停住了，游戏怎么再告诉他一次
      - 时机: 车队被拦住，每隔一阵
        台词:
          - 播报: 原文。
    结束: 这一段怎么结束，剧情上怎么交代下一段

胜利:
  镜头: 结尾镜头给玩家看什么
  台词:
    - 沃斯: 原文。
失败:                            # 每个失败条件一条，说清原因（P11）
  - 原因: 车队被劫走两辆
    台词:
      - 播报: 原文。

示意图:                           # 玩家眼里的地图
  地图: sapporo                   # 这关的实际地图（experimental/cnv/maps 里的模块）；还没有地图就不写
  可玩区:                         # 每一段玩家看得见、走得到的范围，每段都要写
    开场: corridor                #   有地图：写地图 BORDERS 里的名字（任务切边界用的那个）
    北营: west of the canal       #   没地图：写格子上的框 [x0, y0, x1, y1]
  地方:                           # 每个地名一行
    - {名: 一号广场, 块: plaza 1, 用途: 前线, 开: 开场, 又名: [巷口]}
    - {名: 海滩, 点: beach, 用途: 前线, 开: 布防}
    #  块：地图地块用途表（LAYOUT.blocks）里的一块，写它的 what；用途要和那一块一样
    #  点：地图上的一个地点（SITES），也可以写几个，框住它们全部
    #  没地图时改写 位、大：在 100×60 的格子上的中心和宽高，x 往东、y 往南
    #  用途：前线 / 支线 / 通道 / 后方 / 远景（和第 3 步的地块用途表一样）
    #  开：从哪一段开始走得到，写段名；地方要落在那一段的可玩区里
    #  又名：剧本里还会怎么提到它
  路:                             # 没地图时才要：两两相连的地名（有地图就画地图自己的路）
    - [起步, 一号广场]
  路线: [convoy start, approach 1, halt]   # 可选：车队或主路要走的地方；有地图时可以写地图的地点，线就沿着真实的路走
```

台词一律写成 `键: 原文` 一行，键是 [cast.md](cast.md) 里的。只说原版台词的角色（谭雅、百合子……）不能有这一行，要写成镜头里的动作。

`示意图` 是总控 2026-10-28 加的（用户在网页里缺"玩家当前看到的地图"）。同一天用户又要求"按实际的地图划分区域，并指出当前可看到的区域"，所以有实际地图的关，地方对到地图的地块用途表和地点上（[flowmap.py](flowmap.py) 换算），网页拿地图本身的地形、路和地块画底图；每一段的 `可玩区` 框出来，框外压暗。还没有地图的关（例如 S1，第 2 层才出图）仍在格子上写设想。网页拿镜头的 `看`、事件的 `时机`、目标的 `题` 去匹配地名和又名（长的先匹配），匹配上的地方在小地图上框出来，目标也标在那里。所以镜头和目标里提到地方时，用示意图里的名字或又名；一个又名只能给一个地方。

## 三、写法准则

（三关校准之后按用户的意见改这里，再重新产出。第 0～15 条是第一版，第 16～20 条是用户 2026-10-29 的五条审核标准。）证据是原版 40 关怎么告诉玩家做什么：[teardowns/telling.md](../teardowns/telling.md)，下面括号里的数字都出自那里。

0. **规模跟着位置走**（P31）：先认这一关是前期、中期还是后期，按 [principles.md](../principles.md) P31 的下限写够段、主目标、地图变化和动词。后期关要给基地，要把前面给过的工具拿出来一起考一次。类型（突击、护送……）只说核心动词，不说规模。
1. **开场短**：交还控制前不超过约 20 秒（原版中位 18 秒），镜头指一两处地方。"你是谁、为什么来"放进简报，不放进关内开场。
2. **简报**：四到八句（原版简报视频 23 秒）。第一句是钩子（局势或情绪），中间讲敌人、地点、手里有什么，最后一句是命令或一句俏皮话。
3. **目标原文**：题是"动作 + 对象"，六到十个字（原版 4 个英文词，"摧毁"开头的占三成）；说明一到两句，先说为什么，再说怎么做、在哪里。
4. **每个主目标都有一句人话，最好在目标亮出之前**（原版 77% 有人声，54% 在目标之前）。目标在玩家没去过的地方时，还要**指过去**：镜头、揭图、小地图信号、闪烁选一样（原版 58%）。只靠任务菜单的不超过一成。
5. **换段是一段小过场**：黑边 → 镜头摇到新东西 → 交还控制 → 一句话 → 亮目标，整段十到三十秒（原版直布罗陀、敖德萨都是这样）。
6. **谁说什么有分工**：情报官是"告诉你做什么"的主声音（原版 40 关里 37 关是这样）；上级下命令、做评价；反派**在玩家刚取得进展时**出声嘲讽或气急，每关三到五次；英雄只能说原版台词，性格靠动作和原版语音。
7. **提醒按条件说一次，不反复唠叨**：原版几乎没有"隔一阵再说一遍"的提醒（全部 40 关只有 4 处循环）。写"玩家没做某事 / 拖了约两分钟 → 谁说一句"，可以顺手亮出一个奖励目标；"出事了"（车被打、英雄快死）配小地图信号说一次。
8. **文字只给新机制和失败原因**：新单位头上挂信息框，玩家没用过才出现；失败原因用字幕写。别的都用人声。
9. **新东西照原版教新能力的五步**：镜头指到它 → 停一下 → 给到手（信息框）→ 一句话讲怎么用 → 马上来一道只能用它解的题。
10. **台词**：照配音线术语表的翻译原则写，短、口语，数字写汉字，不用括号和英文。**播报先用原版原话**：配音工具只认一字不差（不算标点）的原版句子，差一个字就要新配；原版句子在配音线的 `lines/eva.csv`，按阵营分（盟军 `Aeva_`、苏联 `Seva_`、帝国 `Ieva_`）。意思对得上就照抄原版（"侦测到敌方飞机。""关键单位遭到攻击。""援军已抵达。"），原版没有的（"冰墙已就位。"）才写新句，flowcheck 把新句和最接近的原版列出来。配音线按"说话人 + 原文"查台词编号，所以台词定稿后改字要告诉配音线。一句约十六个字，不超过三十个字（原版一句 3.5 秒）；小窗通讯一段一到三句、约三十个字（原版 8.6 秒）。
11. **人设**：每个角色的口气照 [cast.md](cast.md) 的"说话的样子"。黑尔常常在得意时被下属打断。
12. **剧情转折 = 玩法转折**（P12）：每段的"结束"要交代下一段为什么发生，而且玩家要做的事真的变了。
13. **胜利**：镜头对准主角或护送的东西，一两段通讯，交代下一关为什么发生（大纲 v6）。`引出下一关` 里还写下一关玩家手上因此多了或少了什么（P12 跨关的建议，例如 A7 自由号迫降 → A8 归玩家）。**失败**每个原因一句，说清是哪里出了事（P11）。
14. **不写机制细节**：玩家看得见、听得见的写；脚本怎么判定的不写。
15. **承诺的事要对得上已确认的引擎事实**（总控 2026-10-28）：目标、说明、台词里说玩家能做的事，先查 [mechanics.md](mechanics.md)。"不能做"的不许写（例如修理厂修不了盟友的车、冰墙立在桥面上挡不住、篱笆拦不住步兵）；"待验证"的可以写，但要列进 `用到的机制`，第 3 层先测；表里没有的，先补一行再写。

下面五条是用户 2026-10-29 给第 1 层加的审核标准，原话："这次重点检查游戏演出的质量……在游戏设计的时候，可以多参考心灵终结的战役地图设计，尽管它的难度过大，但其设计思路是十分超前的"。每条对应 yaml 里的一项必填内容，准则和证据在 [principles.md](../principles.md) P32～P35、P24，原版和心灵终结的做法在 [retail-review](../teardowns/data/retail-review.md)、[mental-omega-missions](../teardowns/data/mental-omega-missions.md)。

16. **一关一个完整的故事**（`故事`、`人物`，P32）：开头说谁想要什么、为什么是今天；至少三处起伏，顺逆都有；结尾说谁得到、谁失去。说三句以上台词的人，每人写想要什么和一处转折，玩家要从台词或镜头看得出来。人物靠选择刻画，不靠自我介绍；英雄只说原版台词，转折写成动作。
17. **地图分段打开，最后一段也不留大片空地**（`示意图/可玩区`，P18、P24）：每段的可玩区只框这一段要用的地方；后面的段扩开时，新开的地方都要有用。最后一段里，离每个地方和路线都远、连成一片的空地，不超过玩家能走的地面的 15%（flowcheck 量，查看器在地图上用红色斜线标出来）。超了就缩小可玩区，或者给那块地一个用途（一路反扑、一个奖励、一条绕路）。
18. **至少两种解法，平推要更贵**（`开局`、`解法`、`平推会怎样`、奖励的 `回报`，P33）：先写开局手上有什么、敌方压力多大能不能拆；再写至少两种打法，每种配一个游戏里的提示（台词、说明、镜头、看得见的东西）；奖励目标写回报，最好是下一段的工具（P16）。按用户的打法写"平推会怎样"：他会按敌方兵种换兵、微操、先拆光压力来源，能拆的计时对他没用；所以结尾要留一样拆不掉的压力，能拆的源头要么拆了有代价，要么拆它就是一种解法、写进目标栏。
19. **意外：初见难应对，二周目能准备**（`意外`，P34）：每关至少一处（背叛、科技被收走、兵力受限、援军不可信、计划提前）。写初见怎么撞上、伏笔在哪（简报或更早的段，二周目看得出）、老手提前准备什么、当场怎么补救。不许没预警就收走玩家的大部分军队（心灵终结挨骂的那次）；前期关的意外要轻。
20. **会坏档的地方放保底援军**（`保底`，P35）：钥匙单位全死、没兵没钱还有一大段，这类地方写触发条件（这一段没完成、某种兵少于若干个）、援军、从示意图上哪里来、谁说一句。每处只送一次，够补救不够平推。每个意外的 `补救` 都指向一条保底。保底承诺的是"兵少补援"这个机制（已确认：按几种兵的模板各数一遍再加起来，所以条件写"哪几种兵加起来少于若干个"；要列进 `用到的机制`）。
21. **第 2、3、5 条写成关卡线照着摆的要求**（`摆放要求`，总控 2026-10-29，[ADR 0009](../../adr/0009-one-level-through-all-layers-first.md)）：这三条要到地图和摆放阶段才看得出来，所以流程稿要把它们落到地图上：可玩区每变一次，写哪一段、换成哪块、什么时候切；资源点和伏击点各至少一处，各写在哪个地点、是什么、撑哪种解法；按进度给的援军（交基地也算）写在哪出现。保底在实际地图上也写 `点`。有地图的关，`点` 都是地图的地点名，关卡线拿去直接摆；没地图的关写示意图里的地方，第 2 层出图时补地点。
22. **每段的敌军构成**（`段/敌军`，P29，关卡线 2026-10-29 的离线检查）：写了动词的段，列来的每种兵、它怎么来（摆好的、醒来后出、定时、某个事件）、玩家拿什么克制。至少两种兵、至少两种不同的克制，不能让一种兵打完一段。**"摆好的"要自己就够多样**：离线检查只推演摆好的兵，AI 后来造的不算；A4 北营原来只摆了帝国武士和坦克杀手，激流气垫船一种兵就打完了。喘息段写"无：为什么"。第 3 层用 `python -I -X utf8 experimental/cnv/offline.py <关>` 量"一种兵能打完多少"，对照这里写的。

## 四、机器检查（只查完整和一致）

`python docs/design/flow/flowcheck.py` 检查所有流程剧本：

- 顶层的键都在，`简报`、`段`、`胜利`、`失败` 都有内容；
- 每一段有 `结束`；有目标的段，每个目标都有 `种`、`题`、`说明`，而且这一段写了 `下一步靠什么`；每个主目标所在的段写了 `卡住了`；
- 每句台词的说话人都是 cast.md 里能说新台词的键；
- 台词里不出现阿拉伯数字、英文字母和括号（配音稿的规矩），一句不超过三十个字（不算标点）；
- `出场单位` 里每个名字都在配音线的术语表、大纲第三节的新单位或策划案编译器的 `glossary.py` 里（配音线仓库不在旁边时跳过这一条，会打印出来）；
- `用到的机制` 的每个键都在 mechanics.md 里，而且不是"不能做"；全文不出现"不能做"那几行的禁用说法；用到的"待验证"机制单独列出来，交给第 3 层先测；
- `示意图`：`用途` 是五种之一，`开` 是这一关已有的段名；每一段都有 `可玩区`，地方落在它开的那一段的可玩区里（远景除外）；一个名字或又名不能同时给两个地方。有 `地图` 时：地图模块存在，`块`、`点`、`可玩区`、`路线` 里的名字都是地图上有的，`用途` 和那一块一样。没有地图时：`位`、`大`、`可玩区` 在 100×60 格子里，`路` 和 `路线` 里的名字都是示意图里的地方；
- **规模（P31）**：`位置` 和关号对得上（1～3 前期、4～6 中期、7～9 后期）；主目标数、段数（有主目标的段）、地图变化（相邻两段的可玩区不同的次数）、局面变化（段数 − 1 + 地图变化）、段的动词种数，都不低于这个位置的下限；有主目标的段写了 `动词`；`基地` 是开局 / 中途 / 无，后期写"无"要有 `无基地的理由`；后期的 `综合` 至少两样，每样都是这条线更早的关给的（照大纲第三节的解锁关）。每关的这几个数会单独打印出来；
- 示意图的可玩区：有地图时，写地图 BORDERS 里的名字，或者用世界坐标 [x0, y0, x1, y1] 提议一条地图还没有的边界（第 2 层加进地图）；
- **五条审核**（第 16～20 条）只查填没填、对不对得上，好不好由用户判断：`故事`、`人物`、`开局`、`解法`、`平推会怎样`、`意外`、`保底` 都在；起伏至少三处、顺逆都有、按段的先后写、段名是这一关的；说三句以上台词的角色（播报除外）在 `人物` 里，`谁` 是 cast.md 的键，转折落在这一关的段上；解法至少两种，各有提示；每个奖励目标有 `回报`；最后一段连成一片的空地不超过 15%；意外的伏笔在简报或意外所在的段以前，`补救` 是这一关的一条保底；保底的 `从哪来` 是示意图里的地方，有保底就要在 `用到的机制` 里列"兵少补援"。`摆放要求`（第 21 条）：可玩区每变一次都有一条 `边界`，`换成` 和示意图一致、写了 `何时`；资源点、伏击点各至少一处；资源点、伏击点、援军的 `地方` 是示意图里的、`段` 是这一关的；有地图时它们和每条保底的 `点` 都是地图的地点。`段/敌军`（第 22 条）：写了动词的段都有，每条有兵、怎么来、克制，兵在 `出场单位/敌` 里，至少两种兵、两种克制（或者写"无：为什么"）。每个问题后面标着是第几条，查看器按条分开放；
- 关号和文件名一致。

查看器多一种看法"五条审核"：一条一块，放这一关填的内容和机器查出的那一条的问题；第 2 条那块是每段的小地图，空地用红色斜线标出来，最后一段标着占多少。

另外列两样给写的人看（不算错）：用到的"待验证"机制；没框到任何地方的镜头和目标。后一样多半没事（"镜头回到车队""百合子必须活着"），但如果镜头明明在指一个地方却没框上，就是示意图漏了这个地名，或者剧本换了说法。

正文里提到单位时用和 `出场单位` 一样的叫法；中文自由文本里的单位名机器分不准，这条靠写的人自己守。

好不好、像不像、沉不沉浸，由用户读了判断，机器不查。
