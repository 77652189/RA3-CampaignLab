# 策划案模板的增补建议

**只是建议。** 策划案（`docs/story/plans/*.md`）、编译器 `experimental/cnv/plan.py` 和 `plancheck.py` 归关卡线；这里写要加什么、为什么、plancheck 能查什么，由关卡线决定怎么落。依据是 [principles.md](principles.md)，括号里是准则编号。

现在的策划案管"机制"这一层管得很全：开局、机关、段、目标、进攻、规则、输赢、检查，`plan_show` 还对照原版查分段数、第一波时间、来源和上限。缺的是上面两层：**动态**（玩家会怎么想、怎么选）和**体验**（玩家该感受到什么）。所以加的栏目都放在 yaml 之外或作为新的 yaml 顶层键，编译时不读，只给 `plan_show` 和 plancheck 用。

## 一、加哪几栏

建议放在"定位"之后、"开局"之前，按顺序写；它们决定后面所有 yaml 怎么写（P1）。

### 1. 体验目标（P1）

一句话，写玩家的感受，不写机制。再写一张"情绪弧线"小表：每段一行，玩家的感受 + 对照的原版关。

```yaml
体验:
  目标: 冰是借来的时间：冻早了会化，冻晚了来不及；冻对了，车队一路不停
  弧线: {会场: 拮据, 北营: 掌控, 最后一程: 高潮}
```

### 2. 每段的"动词"和"决策"（P2、P5）

给 `段` 的每一项加两个键，编译不读：

```yaml
段:
  - 名字: 会场
    动词: 护送            # 这一段玩家主要做的事：护送 / 守 / 攻 / 潜入 / 建 / 追 / 解谜
    决策:
      - 选: [先冻, 先打碎, 硬扛]
        代价: [冰 30 秒就化、工兵要活着到门口, 要兵要时间, 车停在火力下挨打]
    教: 冰幕工兵         # 这一段在新机制上走到哪一步：教 / 练 / 考 / 变（P4）
    张力: 3              # 0～5，这一段的峰值（P7）
```

### 3. 张力曲线（P7）

`plan_show` 已经能出节拍表（每段几点开始、每路进攻几点来）。建议它再画一条按分钟的粗线：段的 `张力` 值 + 进攻波次叠加（每一波在它开始的那一分钟 +1）。策划写的 `张力` 和算出来的对不上，就是一个要看的地方。

### 4. 信息表（P10、P11）

A4 已经有"玩家可能不知道的事"（玩家不知道 / 后果 / 怎么告诉）。建议所有策划案都有这张表，并加一列"失败时屏幕上说什么"。

### 5. 空间表（P13）

每段一行：这一段用的边界、新开的地点、每个决策对应的两块地或两条路。

### 6. 布局（P17～P20）

放在"开局"之前，先定布局再摆兵。理由和原版的数字见 [teardowns/layout.md](teardowns/layout.md)。

```yaml
布局:
  体验: 推进            # 推进（背靠角落或边）/ 被包围（四处救火，才放中间）
  出生点: 第一块的西边，路的西头   # 写位置，也写为什么在这
  背后: 地图边          # 出生点背后是什么：地图边 / 水 / 悬崖 / 自己的基地
  推进方向: 东           # 主目标在出生点的哪边
  敌人来路: [东（街）, 北（广场门）]   # 第一块里敌人从哪几个方位来
  路线: {主路: 大街, 备选: 1 号广场后巷（要先清掉巡逻）}
  支线: [{奖励: 占修理厂, 在: 1 号广场后巷, 代价: 绕路、有守军, 回报: 第 2 段修车}]
```

每段的空间表里再加两列：这一段结束时出生点在可玩区的什么位置（角 / 边 / 中）、这一段新开的那一块朝哪个方向长。

### 7. 玩家看见什么（P21～P23）

布局是动态的。每段写一张小表，按时刻排：这一刻玩家看见什么、是被领着看的还是自己找的。理由和原版的数字见 [teardowns/layout.md](teardowns/layout.md) 第三节。

| 时刻 | 可玩区 | 揭开（哪里、永久还是看一眼） | 镜头领着看哪里 | 亮出的目标（领着看 / 自己找 / 走近才亮） | 敌人（睡着 / 玩家推进才动 / 计时） |
|---|---|---|---|---|---|
| 开场 0～15 秒 | 第 1 段走廊 | 全图看一眼，交还控制时收回；走廊永久揭开 | 车队 → 1 号广场冰雕（演示冰雕裂开）→ 2 号广场 | — | 广场里的兵睡着 |
| 交还控制 | 同上 | 走廊 | — | 主：护送（领着看）；奖励：修理厂（走近后巷才亮） | — |

要写成 yaml 的词，现在缺两个：
- 目标的 `亮出: <条件>`（默认仍是"段开始 2 秒起每隔 4 秒亮一个"），让奖励能等玩家走近才亮；
- 动作 `{揭开: <地点>, 半径: 300, 永久: 是}` 和 `{揭全图: 看一眼}`（交还控制或下一段开始时收回）。

`{镜头: <地点>}` 已经有了。

### 8. 地形和地块用途（P24～P27）

布局草图的一部分（[charter.md](charter.md) 第二节"第 3 步的布局草图要写清地形"）。理由和原版的数字见 [teardowns/terrain.md](teardowns/terrain.md)。分两半：

- **地图一侧**（地图模块，地图线 / 关卡线）：每个形状写 `role`，即这块地的用途。
- **策划案一侧**：每块地在哪一段打开、上面放什么、支撑哪个决策。

```yaml
地形:
  花样: [隘口, 高低层, 水和桥]     # 至少两种，选这一关的动词用得上的（P25）
  动词怎么用: 冰墙封 120 宽的口子；广场高出路面，冰雕兵从高处扑下来；运河桥是最后一个口子
地块:
  - {块: 第 1 段走廊, 段: 1, 用途: 通道, 有: [1、2 号广场的门], 决策: 冻 / 碎 / 扛}
  - {块: 后巷, 段: 1, 用途: 支线, 有: [修理厂, 巷口冰雕], 决策: 去不去冒险}
  - {块: 北高原, 段: 2, 用途: 前线, 有: [北营, 正坡, 后坡], 坡道: [正坡（宽）, 后坡（窄，通电厂）]}
  - {块: 西南丘陵, 用途: 远景, 怎么隔开: 悬崖围死、不留坡道}
主路:
  隘口: [1 号广场门, 2 号广场门, 运河桥]   # 至少一个（P27）
  旁边的高地: [北侧街区（后巷）, 南高原]
空军:                                   # 地形管不住空军（P28）
  玩家: 不给机场                         # 不给 / 只给 <飞机> / <第几段> 起给 <飞机> / 不限
  敌人据点防空: 不用（玩家没有飞机）     # 不限玩家空军时必须写清哪些据点配防空
  敌人空军: 第 3 段第 3 档天狗从海上来，逼玩家留防空
```

要编译器加的词：`禁造: [机场, ...]`、`放开: {当: <条件>, 造: [<飞机>]}`，也就是给玩家写 `ALLOW_DISALLOW_ONE_BUILDING` 和 `PLAYER_LOCK_PLAYER_TECH`。现在编译器只给敌方 AI 写这两个动作。

每块写清"用途"。用途只有五种：前线、支线、通道、后方、远景。"空地"不是一种用途：走得到、没事做的块不许出现（P24）。

### 9. 敌军构成和克制（P29、P30）

每段写一张小表：来的是哪几种兵、各专打什么，玩家这时手里拿什么克制，兵种以外还有什么办法。

```yaml
敌军构成:
  - 段: 会场
    敌人: {帝国武士: 打步兵, 坦克杀手: 打车, 爆裂无人机: 打车}
    玩家手里: [冰幕工兵, 守护者坦克, 维和步兵, 标枪兵]
    兵种以外: [冰墙封门, 后巷高处]
    最强的敌人: 坦克杀手（2 号广场杀不完，只能冻）
禁造: [机场, 幻影坦克, 谭雅]    # 前段禁掉"什么都打"的兵
```

`敌军构成` 是给人看的新键，编译器不读；兵的数量照旧写在 `开局`、`进攻`、机关里。第 4 步用 [units_measure.py](teardowns/data/units_measure.py) 量编好的地图，对照这张表。

### 10. 副指挥官（只在剧情里有友军的关，用户 2026-10-28 定）

大多数关没有这一节。有的关写清三件事：它管哪一块、玩家能叫它做什么、它会不会替玩家把仗打完。

```yaml
副指挥官:
  阵营: 盟军
  角色: 盟军联络官          # 剧情里的人，头像和语音跟着他走（skirmish-ai.md 第三节）
  开局: {基地: 西岸, 部队: [守护者坦克 x4, 维和步兵 x6]}
  管哪一块: 西岸那条路      # 玩家守东边，两边各守一路
  热点:                     # 玩家能叫它去的地方，每个对一个状态
    - {地点: 北面雷达站, 做: 进攻, 从: 第 2 段}
    - {地点: 观测站, 做: 守住}
  上限: 不派飞机、不造重坦   # 别让它替玩家平推（P29）
```

编译器现在没有这些词：要 Player_2 当友军指挥官（自己的基地、资源共享）、热点、它自己的 AI 性格。归关卡线，先做 [skirmish-ai.md](skirmish-ai.md) 第五节那个检查。

## 二、plancheck 能查什么

按"能机器判断"排。每条写查什么、为什么、需要的新信息。

|---|---|---|---|

## 四、落地顺序建议

1. **先加第 3、10、15 条**：只用已有信息，就能抓到现在最普遍的三个问题（新单位不是钥匙、护送不依赖玩家、压力开关一个模子）。布局这边先加第 19、22、26 条（出生点在中间、目标贴着出生点、出生点是模板默认值），我们 11 关里分别有 9、5、5 关会被它们抓到（A4、A5、A7、A8、J3 的出生点彼此相距不到 300：7 张新地图都从 `island.py` 复制了 `start` 那组地点）。地图这边也可以加一条：地图模块不许原样复制别的地图的 `start`，要按这张图的玩法给。
   敌军构成这边先加第 40、41 条：我们 11 关里分别有 10 关、10 关会被抓到（只有 J5 有 6 种敌人；只有 J7 没有一段能被一个兵种对付九成以上）。
   地形这边先加第 32、33 条（用到不到一半或空地太多、地形花样少于两种）：我们 11 关里分别有 10 关、8 关会被抓到，只有 A8 过得了第 32 条。第 38 条用的 `禁造` / `准造` 编译器已经有了（2026-10-28），现在有基地的 8 关全都会被它抓到。第 34 条要地图模块先有 `role` 字段，跟生成器一起做（[terrain](teardowns/terrain.md) 第四节）。
2. 再加 `体验` 和每段的 `动词` / `决策` / `张力` 新键，先在 A4 返工时试用；
3. 最后让 `plan_show` 画张力曲线。
